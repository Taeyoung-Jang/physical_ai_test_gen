# 검토된 행동 기록으로 자동 AFS 탐색하기

최근 같은 로봇 조건의 성공·실패를 입력하면, 다음 환경 선택부터 실행·분석까지 한 번의
명령으로 반복합니다. 매 실험마다 사람이 수치나 다음 명령을 고를 필요가 없습니다.
기존 자동 AFS/Random 파일럿과 별개인 **외부 이력 기반 개발 탐색**입니다.
이 결과로 Random 대비 Gain이나 일반화 성능을 주장하지 않습니다.

## 유지하는 조건과 탐색 범위

로봇 모델, 목표, 회당 호출 예산, 밀기 가능 여부, 내비게이션 완료 조건과 HTTP 제한은
입력 기록에서 가져와 고정합니다. 로봇의 행동·중간 목표는 여전히 로봇 시스템이 결정합니다.
AFS는 기준 장면의 환경 파라미터 하나를 바꾸거나 명시적인 반복을 선택할 뿐입니다.
경로 없음·접촉·기술 실패를 임의로 goal FAIL로 바꾸지 않습니다.

현재 검토된 입력은 다음 두 기록입니다. 변경 전 로봇의 과거 성공 기록과 섞지 않습니다.

- `20261003T150653_133405Z`: 측면 비율 0.5, VALID/FAIL.
- `20261003T154614_537450Z`: 측면 비율 0.75, VALID/PASS.

두 기록 모두 Luna, 회당 10회 호출, `goal_outcome_v1`, `goal_dwell_v1`, 밀기 활성화,
HTTP 읽기 제한 300초입니다. 로봇 코드·자산·실행 환경·원본 해시를 시작 전에 검사하고,
각 실행 후 실제 condition ID와 장면을 다시 비교합니다.

v4의 18축을 사용합니다. 상자 질량·마찰·측면 배치·목표 주변 X 위치, 바닥 마찰,
통로 폭, 두 고정 장애물 각각의 X 위치·측면 비율·크기 X/Y·높이·회전입니다.
새 점프 기술, 경사 장면, 사람이나 인식 센서는 이번 변경에 포함되지 않습니다.
폭·회전·크기 변경은 파생된 물체 Y 위치도 바꿀 수 있습니다.

## 자동 선택 규칙

첫 실험부터 LLM 가설을 요청합니다. 기존에 관측 경계가 있어도 0.625 같은 중간값 시험을
선행 조건으로 요구하지 않습니다. 이후 가설 슬롯과 국소 검사 슬롯을 번갈아 사용합니다.

1. 가설 슬롯은 실제 행동 요약, SceneGraph, 성공·실패, 로봇 조건과 남은 선택 가능 축을
   제공합니다. LLM이 제시한 1~4개 범위에서 근거와 가설에 따라 **끝점 하나만** 선택합니다.
2. 국소 슬롯은 같은 장면에서 PASS/FAIL이 섞이면 제한된 반복을 먼저 고려합니다.
   없거나 반복 예산을 썼다면 관측된 단일 축 성공·실패 구간의 미시험 중간값을 고려합니다.
   가능한 국소 검사가 없으면 새 LLM 가설을 요청합니다. Random으로 몰래 대체하지 않습니다.
3. 기본값은 같은 축의 새 변경 실험 최대 2회, 명시적 반복 최대 1회입니다. 바로 이전
   변경 실험의 축은 다음 변경에서 제외합니다. 반복을 사이에 넣어도 이 제한은 풀리지 않습니다.
   소진되거나 일시 제외된 축은 요청 스키마와 실행 전 검증 양쪽에서 막습니다.
4. 이미 본 장면과 비슷한 실패를 반복하는 가까운 후보는 기존 중복·행동 패턴 검사를
   재사용해 걸러냅니다. 완화·대안 가설을 요청하며, 더 무겁게 만드는 것이 항상 유익하거나
   마찰 감소가 항상 쉽다고 가정하지 않습니다.

회당 하나의 파라미터를 변경하지만 여러 실험을 거치며 다른 축을 탐색할 수 있습니다.
새 축, 새 행동 패턴, LLM의 설명은 **검증된 새 실패 유형이나 원인**을 뜻하지 않습니다.
현재 관측에 PASS가 없으면 성공 측면 탐색을 우선하고, 있을 때는 대안 가설을 우선합니다.

## 예산

`config/afs_autonomous_luna.json` 기본 설정은 다음과 같습니다.

| 항목 | 상한 |
|---|---:|
| 새 로봇 실험 시도 | 6회 |
| 새 AFS 요청 | 6회 |
| 같은 축의 변경 실험 | 2회 |
| 혼합 결과 확인 반복 | 1회 |
| 위 입력 기준 로봇 API | 총 60회 |

제외·중단된 시도도 총예산을 소비합니다. 재개는 남은 예산만 사용합니다. AFS 예산이나
선택할 축이 먼저 소진되면 실험 6회를 채우지 않고 종료할 수 있습니다. **유효 결과 6개를
얻을 때까지 추가 시도하는 설정이 아닙니다.**

과거 로봇 비용, 새 로봇 비용, 새 AFS 비용은 따로 보고합니다. 입력 로봇 archive에 없는
과거 AFS 선택 비용은 알 수 없음으로 표시합니다. 토큰 수신 누락도 0으로 계산하지 않습니다.
출력 토큰 상한이나 기본 시뮬레이션 시간 상한을 추가하지 않았으며, 금액 상한 보장은 아닙니다.

## 실행

기존 실행 환경에서 API 키를 설정한 터미널을 사용하세요. 키 설정은 저장소 README에 있습니다.
먼저 디렉터리로 이동합니다.

```bash
cd /workspace/g1_failure/src/physical_ai_test_gen/scene2test
```

다음은 **새 유료 세션 전체를 시작하는 한 줄 명령**입니다. 새 시각 폴더에 저장하며,
다시 입력하면 새 예산의 다른 세션이 생깁니다. 기존 세션을 이어갈 때는 아래 재개 명령을 사용하세요.

```bash
uv run --no-sync python tools/run_afs_autonomous.py run --live --config config/afs_autonomous_luna.json --run /workspace/g1_failure/runtime/robot_goal_agent/20261003T150653_133405Z --run /workspace/g1_failure/runtime/robot_goal_agent/20261003T154614_537450Z
```

유료 실행 없이 확인하려면 `run --live` 대신 `plan`을 사용합니다. 원본 읽기와 로컬 해시
검사만 하며 API·로봇·새 세션 디렉터리를 만들지 않습니다.

```bash
uv run --no-sync python tools/run_afs_autonomous.py plan --config config/afs_autonomous_luna.json --run /workspace/g1_failure/runtime/robot_goal_agent/20261003T150653_133405Z --run /workspace/g1_failure/runtime/robot_goal_agent/20261003T154614_537450Z
```

출력된 `AFS_AUTONOMOUS=` 경로를 복사해 다음 자리표시자를 바꾸면 재개할 수 있습니다.

```bash
uv run --no-sync python tools/run_afs_autonomous.py run --live --session /workspace/g1_failure/runtime/afs_autonomous/실제_세션_폴더
```

보통 `--max-new-attempts`는 필요 없습니다. 지정하지 않으면 남은 승인 예산을 자동 실행합니다.
점검하려고 한 회만 실행할 때 `--max-new-attempts 1`, 저장된 pending 결과 수집만 시도할 때
`--max-new-attempts 0`을 쓸 수 있습니다. 0은 새로운 API·로봇 호출을 하지 않지만,
이 CLI에서는 `--live`와 키 설정을 요구합니다.

## 중단과 결과 확인

유효한 PASS와 FAIL 모두 다음 탐색으로 이어집니다. API 오류, 잘못된 응답·근거,
실행 환경 변경 또는 제외 결과는 멈추고 원인을 기록합니다. SQLite intent와 OS 잠금으로
동시 실행을 막고, 이미 요청한 API나 실행한 로봇을 자동 재전송하지 않습니다.
응답/완료 archive가 저장된 경우 같은 세션의 재개에서 수집할 수 있습니다.
저장 응답이 없는 불명확한 요청은 재개해도 중단 상태를 유지합니다. 원본 응답을 고치거나
DB를 수정해 우회하지 마세요. 별도 확인이 필요합니다.

검토가 끝난 **제외 결과** 뒤의 남은 새 시도를 허용할 때만 재개 명령에
`--continue-after-exclusion`을 붙입니다. 제외된 실험을 재시도하거나 예산을 늘리지 않습니다.
이 옵션은 손상된 응답, 불명확한 요청, 소스 변경을 무시하는 기능이 아닙니다.

산출물은 `/workspace/g1_failure/runtime/afs_autonomous/<시각>/` 아래에 있습니다.

- `protocol.json`, `campaign.sqlite3`: 동결된 조건·예산과 상태 전이 기록.
- `proposals/`: 요청·응답 원본, 사용량과 후보 선정 근거.
- `attempts/attempt_*/rollout/`: 실제 로봇 결과, 행동 기록, `report.html`, MP4. GIF 없음.
- `errors/`: 비밀정보를 제거한 예외 종류·메시지·호출 위치.
- `reports/<시각>/report.html`: 가설→장면→실제 행동·판정·MP4와 비용 연결.
- 보고서의 `search_diagnostics.json`: 새 실행만의 반복 패턴/관측 구간과 상속 이력 포함
  분석을 분리. `hypothesis_reviews.json`은 가설과 결과를 연결하지만 원인을 확정하지 않음.
- 보고서의 `behavior/memory.json`: 성공 대조·실패·혼합 반복과 근거를 기존 회귀 도구에
  넘길 수 있는 자산. 회귀 실행은 별도 예산이며 자동으로 시작하지 않음.

기존 동결 campaign과 원본 결과는 수정하지 않습니다. 폭 실험의 중단도 유지합니다.
이번 기능은 오프라인에서 검증했으며, 이 새 루프를 이용한 유료 탐색 성과는 아직 없습니다.
