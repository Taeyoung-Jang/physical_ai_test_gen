# 실패 유형 10종과 기존 실험 재분석

## 시스템 계층 관측 후보 12종 (2026-10-19, 오프라인 opt-in)

로봇 본체만이 아니라 Agent의 목표 선택, 경로계획 인터페이스, 학습된 보행 제어기
등을 포함한 전체 시스템의 실패를 표현한다. **증상 분류와 결함 원인 판정은 별개**다.
현재 아카이브에는 카메라 기반 GPT Agent, 경로계획/추종기, 저수준 제어 조건이
기록돼 있다. VLA는 별도 구성요소로 식별·계측되어 있지 않으므로 VLA 오류라는
유형/원인을 만들어내지 않는다. Agent/계획기/제어기/본체 결함도 모두 미확정이다.

새 `system-twelve-v1`은 기존10종에 다음 **관측형 후보**2종을 추가한다.

| 유형 | 포함 조건 | 단정하지 않는 내용 |
|---|---|---|
| `goal_endpoint_rejection` | VALID FAIL·예산 소진·최종 목표 밖. 전체 실행 중 고정 최종 목표점에 대한 `blocked_endpoint`가2회 이상이고 마지막 accepted 행동도 해당 거절 | 도달 불가, 계획기 버그, 인식 오류, 몸체의 이동 불능 |
| `subgoal_completion_loop` | 같은 FAIL 조건. 마지막3회 이상 연속 navigate 결과가 `target_reached`지만 요청점/로봇 모두 최종 목표 밖. 그 연속 구간에 같은 중간목표 도착이2회 이상(허용차2cm) | Agent가 목표를 오해했다는 내부 추론, 필요한 정상 경유 이동을 전부 실패로 간주 |

위 값은 관찰한 개발 데이터에서 정의한 후보 규칙이다. 향후 독립 검증 전 동결해야
하며, 표본을 보고 값을 바꿨다면 새로운 버전으로 분리한다. 정책호출·상태·도구 결과가
불완전하면 UNKNOWN으로 두고 추론 대기 시간을 실제 이동/정체 시간으로 사용하지 않는다.
마지막 로컬 거절 행동을 몰래 건너뛰어 이전 행동을 종료 행동으로 취급하지 않는다.
명시적 `stale_rejected`는 미실행된 기록이므로 실제 이동으로 세지 않는다. 중간의
이 명시적 거절 때문에 그 외 완전한 도구 결과까지 누락으로 취급하지는 않지만,
종료 행동 자체가 거절됐다면 이전 행동을 대신 종료 행동으로 사용하지 않는다.
목표점 허용차는1e-6m, 완료 기준은 원래 task contract와 full-rate 종료 상태를 확인한다.
일반적인 경유점3개 성공만으로는 두 번째 유형이 아니다. 반복 중간목표가 있어야 한다.

종료 시 반복된 제자리 회전 명령은 별도 진단으로만 기록한다. 회전을 지시해 회전한
것은 물리적 이동 불능의 증거가 아니며 실패 유형 수에 추가하지 않는다.
기존10종의 primary와 ambiguity를 보존하고, 기존 primary가 없을 때만 유일한 새
관측을 primary로 선택한다. 한 실패 장면에서 여러 유형 실적을 만들어내지 않는다.
PASS/제외 실행에는 새로운 실패 primary를 붙이지 않는다.

`failure_layers`는 관측된 인터페이스(목표점→경로계획, 중간목표→과제완료)와
아카이브에 실제 기록된 모델/프롬프트/계획기/제어 조건을 보존한다. root cause와
Agent·계획기·제어기·본체 결함은 `UNCONFIRMED`, 별도 VLA는
`NOT_SEPARATELY_INSTRUMENTED`로 남긴다. 원인 확정에는 동일 입력의 구성요소
분리 재생, 명령-실행 추종 비교, 동일 조건 대조 등이 필요하며 별도 승인을 받아야 한다.
네트워크/DNS/응답 타임아웃은 기존처럼 제외이지 로봇/모델 실패 유형이 아니다.

추가로 모델이 반환한 `state_version`이 해당 호출의 `observation_version`과 다르고
실행기가 `stale_rejected`로 기록한 경우 `policy_state_contract` 진단에 원본 행과
해시를 보존한다. 현재 attempt9에서는 관측4에 출력5가 기록돼 있다. 이것은 명령
인터페이스 위반을 직접 관측한 것이지만, 전체 과제 실패의 원인 확정이나13번째
실패 유형이 아니다. 버전은 맞지만 물리 자세가 변해서 거절된 경우와도 구분한다.

```bash
uv run --no-sync python tools/reanalyze_system_failures.py \
  --session /workspace/g1_failure/runtime/trajectory_feedback/20261019T134446_66195/afs
```

이 명령은 새 별도 보고서만 만들고 API/GPU/로봇을 실행하지 않는다. READY 세션도
마지막 저장 보고서의 manifest·episode identity를 검증해 그 시점 스냅샷만 분석한다.
기존 DB나 원본 결과/예산을 바꾸지 않는다. 10종과12종 수치를 나란히 보존하며,
사후 유형 추가를 탐색 성능 향상이나 과거4종 목표 달성으로 소급하지 않는다.
기존6/10종 기본 집계와 AFS 프로필은 유지한다. 새12종은 현재 온라인 AFS 제안에
아직 연결하지 않았다. 향후 연결은 별도 버전·새 조건으로 검증해야 한다.

실제10시도 스냅샷 재분석 보고서는
`/workspace/g1_failure/runtime/system_failure_reanalysis/20261019T155051_917992Z/report.html`이다.
기존9VALID FAIL/1제외는 동일하다. 10종 집계는3종·미분류5개 그대로이고,
12종 후보 프로필에서는 attempt6의 중간목표 반복과 attempt9의 목표점 계획 거절이
추가되어5종·미분류3개다. attempt3의 계획 거절 관측은 기존 조작 실패 primary를

## 유형과 판정 기준

| 번호 | 유형 | 판정 범위 |
|---|---|---|
| 1 | 충돌 | 기존 접촉·종료 정체 규칙 유지 |
| 2 | 도달 불가 | 현재 미지원, static no_path로 대신하지 않음 |
| 3 | 장애물 간섭 | 기존 최근 반복 막힘·근접·종료 정체 규칙 유지 |
| 4 | 목표 위치 점유 | 기존 목표 전체 영역 점유·종료 정체 규칙 유지 |
| 5 | 작업자 안전 위험 | 기존 검증된 사람 proxy 종료 구간 노출 규칙 유지 |
| 6 | 인식 오류 | 현재 미지원, 추정만으로 부여하지 않음 |
| 7 | 넘어짐 | 연속된 저장 상태에서 G1 base 높이 .45m 미만 또는 기울기60도 이상이 .5초 이상 |
| 8 | 이동 정체 | 최근10초에 끝난 이동 실행이2초 이상, 순이동 .05m 이하, 실행 구간 위치 편차 .1m 이하 |
| 9 | 물체 조작 실패 | 물체별 마지막 조작 도구 결과가 rejected/failed/failure/aborted |
| 10 | 목표 완료 실패 | 최종 full-rate 기록에서 목표 영역 안이지만 필요한 체류 시간을 채우지 못함 |

7번은 현재 G1 시뮬레이션의 관측 규칙이지 보편적인 자세·안전 기준이 아니다. 샘플 간격이
.25초를 넘는 등 기록이 불완전하면 UNKNOWN이다. 8번은 추론 대기 시간이 아닌 실제 실행
시간을 사용한다. 정지·제자리 회전 명령, 이미 도착한 부분 목표, 짧은 blocked_endpoint는
자동으로 정체가 되지 않는다. 출발점으로 돌아오는 긴 왕복도 위치 편차 검사로 제외한다.

9번에는 실행 전 거절도 포함한다. 이것이 물리적으로 밀 힘이 부족했다는 뜻은 아니다.
같은 물체에 나중에 성공하면 이전 거절만으로 실패를 부여하지 않는다. 아직 구현되지 않은
기술을 지원한다고 가정하지 않으며, 기록의 알려진 상태만 사용한다. 10번은 모든 예산 종료를
포괄하지 않는다. 목표 밖에서 종료하거나 full-rate 체류 기록이 없으면 해당 유형을 붙이지 않는다.

## 집계 방식

최종 결과가 VALID FAIL일 때만 실패 유형을 집계한다. PASS의 접촉·조작 거절 등은 보조
진단일 뿐 실패 실적이 아니다. 제외된 실험도 실패 유형으로 세지 않는다.

한 실험에 여러 관측이 있으면 기존 규칙의 유일한 대표 유형을 우선 유지한다. 기존 규칙이
서로 충돌해 ambiguous라면 임의로 해소하지 않는다. 기존 대표가 없는 경우에는 넘어짐,
목표 완료 실패, 이동 정체, 물체 조작 실패 순으로 대표1개를 고른다. 이 우선순위는
중복 집계 방지 규약이지 원인 확정이 아니다. 나머지는 `diagnostic_families`로 보존한다.
같은 장면 반복에서 대표가 엇갈리면 기존 집계기의 ambiguity 보호도 유지한다.

새 프로필은 `expanded-goal-behavior-v1`이다. 기존 goal-behavior-v1/v2와6종 기본 집계는
변경하지 않는다. 10종 집계는 `family_inventory=EXPANDED_FAMILIES`를 명시해야 한다.
보고서는 분모10을 표시하고, 미지원·미분류가 있으면 전체 coverage는 null, 관측 하한만
표시한다. 이름을10개 만들었다고10개 검출기나4종 발견이 확보된 것은 아니다.

## 실행 방법

완료된 세션의 저장 기록만 분석한다. API 키나 GPU는 필요하지 않다.

```bash
cd /workspace/g1_failure/src/physical_ai_test_gen/scene2test
uv run --no-sync python tools/reanalyze_failure_types.py --session /workspace/g1_failure/runtime/afs_autonomous/20261018T081720_637822Z
```

개별 기록은 `--run /절대경로/rollout`을 반복해서 지정할 수 있다. 새 출력은 기본적으로
`/workspace/g1_failure/runtime/failure_type_reanalysis/<새시각>/`이다. 기존 출력 덮어쓰기,
원본 실험 내부 저장은 거절한다. 세션 입력은 완료 상태와 보고서 manifest를 확인하고,
각 rollout의 선언된 아카이브 해시도 검증한다.
