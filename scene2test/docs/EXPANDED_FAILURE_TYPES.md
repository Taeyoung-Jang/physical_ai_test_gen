# 실패 유형 10종과 기존 실험 재분석

실제 시뮬레이션에서 기존6종으로 설명하기 어려운 행동 현상이 관찰되어 분류 대상을
10종으로 확장했다. 목표는 같은 최종 목표·서로 다른 환경의 유효 표본에서 FDR30% 이상과
10종 중4종 이상 발견이다. 기존 결과를 새 성과로 덮어쓰지 않고 별도 사후 분석으로 저장한다.

## 유형과 판정 기준

| 번호 | 유형 | 판정 범위 |
|---|---|---|
| 1 | 충돌 | 기존 접촉·종료 정체 규칙 유지 |
| 2 | 도달 불가 | 현재 미지원, static no_path로 대신하지 않음 |
| 3 | 장애물 간섭 | 기존 최근 반복 막힘·근접·종료 정체 규칙 유지 |
| 4 | 목표 위치 점유 | 기존 목표 전체 영역 점유·종료 정체 규칙 유지 |
| 5 | 작업자 안전 위험 | 기존 검증된 사람 proxy 종료 구간 노출 규칙 유지 |
| 6 | 인식 오류 | 현재 미지원, 추정만으로 부여하지 않음 |
| 7 | 넘어짐 | 연속된 저장 상태에서 G1 base 높이 .45m 미만 또는 기울기60도 이상이 .5초 이상 |
| 8 | 이동 정체 | 최근10초에 끝난 이동 실행이2초 이상, 순이동 .05m 이하, 실행 구간 위치 편차 .1m 이하 |
| 9 | 물체 조작 실패 | 물체별 마지막 조작 도구 결과가 rejected/failed/failure/aborted |
| 10 | 목표 완료 실패 | 최종 full-rate 기록에서 목표 영역 안이지만 필요한 체류 시간을 채우지 못함 |

7번은 현재 G1 시뮬레이션의 관측 규칙이지 보편적인 자세·안전 기준이 아니다. 샘플 간격이
.25초를 넘는 등 기록이 불완전하면 UNKNOWN이다. 8번은 추론 대기 시간이 아닌 실제 실행
시간을 사용한다. 정지·제자리 회전 명령, 이미 도착한 부분 목표, 짧은 blocked_endpoint는
자동으로 정체가 되지 않는다. 출발점으로 돌아오는 긴 왕복도 위치 편차 검사로 제외한다.

9번에는 실행 전 거절도 포함한다. 이것이 물리적으로 밀 힘이 부족했다는 뜻은 아니다.
같은 물체에 나중에 성공하면 이전 거절만으로 실패를 부여하지 않는다. 아직 구현되지 않은
기술을 지원한다고 가정하지 않으며, 기록의 알려진 상태만 사용한다. 10번은 모든 예산 종료를
포괄하지 않는다. 목표 밖에서 종료하거나 full-rate 체류 기록이 없으면 해당 유형을 붙이지 않는다.

## 집계 방식

최종 결과가 VALID FAIL일 때만 실패 유형을 집계한다. PASS의 접촉·조작 거절 등은 보조
진단일 뿐 실패 실적이 아니다. 제외된 실험도 실패 유형으로 세지 않는다.

한 실험에 여러 관측이 있으면 기존 규칙의 유일한 대표 유형을 우선 유지한다. 기존 규칙이
서로 충돌해 ambiguous라면 임의로 해소하지 않는다. 기존 대표가 없는 경우에는 넘어짐,
목표 완료 실패, 이동 정체, 물체 조작 실패 순으로 대표1개를 고른다. 이 우선순위는
중복 집계 방지 규약이지 원인 확정이 아니다. 나머지는 `diagnostic_families`로 보존한다.
같은 장면 반복에서 대표가 엇갈리면 기존 집계기의 ambiguity 보호도 유지한다.

새 프로필은 `expanded-goal-behavior-v1`이다. 기존 goal-behavior-v1/v2와6종 기본 집계는
변경하지 않는다. 10종 집계는 `family_inventory=EXPANDED_FAMILIES`를 명시해야 한다.
보고서는 분모10을 표시하고, 미지원·미분류가 있으면 전체 coverage는 null, 관측 하한만
표시한다. 이름을10개 만들었다고10개 검출기나4종 발견이 확보된 것은 아니다.

## 실행 방법

완료된 세션의 저장 기록만 분석한다. API 키나 GPU는 필요하지 않다.

```bash
cd /workspace/g1_failure/src/physical_ai_test_gen/scene2test
uv run --no-sync python tools/reanalyze_failure_types.py --session /workspace/g1_failure/runtime/afs_autonomous/20261018T081720_637822Z
```

개별 기록은 `--run /절대경로/rollout`을 반복해서 지정할 수 있다. 새 출력은 기본적으로
`/workspace/g1_failure/runtime/failure_type_reanalysis/<새시각>/`이다. 기존 출력 덮어쓰기,
원본 실험 내부 저장은 거절한다. 세션 입력은 완료 상태와 보고서 manifest를 확인하고,
각 rollout의 선언된 아카이브 해시도 검증한다.

## 최근 6회 결과

재분석 보고서:
`/workspace/g1_failure/runtime/failure_type_reanalysis/20261018T130328_693125Z/report.html`

PASS3/FAIL3/제외0, FDR50%는 그대로다. 기존6종 분석은0종, 확장10종 분석은1종이다.
회차3의 거리 .218747m·체류 .655/1초를 목표 완료 실패로 분류했다. 같은 회차의 과거
unsupported_box_face는 조작 실패 보조 진단으로 남기되 별도 발견1종을 더하지 않았다.
나머지 실패2개는 미분류로 남겼다. 넘어짐·실제 실행 정체를 관측했다고 만들지 않았다.

이는 같은 저장 기록을 넓힌 기준으로 설명한 사후 결과이며, 새 AFS 실험의 유형 발견
실적과 구분해야 한다. FDR30%와4종의 공동 목표는 여전히 미달성이다.

확장 측정은 이제 opt-in AFS 선택에도 연결됐다.
[10종 AFS 연결·실행 안내](AFS_EXPANDED_TEN.md)의 `afs_expanded_ten_luna.json`을 사용한다.
기존 설정은6종 계약을 유지한다. 기존 동결 세션을 새 소스로 재개하거나 판정을 덮어쓰지 않는다.
