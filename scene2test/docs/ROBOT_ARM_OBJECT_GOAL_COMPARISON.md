# Object / Goal AFS–Random comparison

Object의 **버터를 바구니에 넣기**, Goal의 **가운데 서랍 열기**를 각각 독립 비교합니다.
직전 기본 환경의 1회 실행은 두 태스크 모두 native PASS였지만, 그 결과를 새 탐색의
bootstrap이나 AFS 이력으로 가져오지는 않습니다. 기존 Spatial 실험과 소스도 유지합니다.

## 실행

`scene2test`에서 다음 명령을 실행합니다. AFS는 기존 로봇팔 실험과 같은 OpenRouter
`openai/gpt-6-luna-pro`를 사용하므로 터미널의 `OPENROUTER_API_KEY`가 필요합니다.
키를 출력하거나 파일에 저장하지 않습니다. 로봇은 태스크 묶음별 로컬 GR00T입니다.

```bash
set -o pipefail
bash tools/run_robot_arm_object_goal_comparisons.sh --live 2>&1 | tee zz_run_object_goal_comparisons.log
```

계획만 확인하려면 옵션 없이 실행합니다. 저장 결과의 집계는 다음 명령입니다.

```bash
bash tools/run_robot_arm_object_goal_comparisons.sh --status
```

이미 준비된 출력 폴더에 실행합니다. init/prepare/폴더 삭제/예산 초기화가 필요 없습니다.
실행 순서는 Object 3세트 후 Goal 3세트이며 한 번에 하나의 새 로봇 에피소드만 시작합니다.
기존 별도 실행 중인 실험의 프로세스는 중지하거나 관리하지 않습니다.

## 반복 수와 동일 조건

| 범위 | AFS | Random | 최대 AFS 요청 |
|---|---:|---:|---:|
| 한 태스크의 한 세트 | 12회 | 12회 | 6회 |
| 한 태스크의 독립 3세트 | 36회 | 36회 | 18회 |
| 두 태스크 합계 | 72회 | 72회 | 36회 |

총 **144개 새 에피소드**, 에피소드당 최대 300 control steps, 총 최대 43,200 steps입니다.
정책 action chunk는 8, 네이티브 제어는 20Hz입니다. API HTTP timeout은 300초이며
자동 재시도나 모델 fallback을 추가하지 않습니다. 모델 revision은 기존과 같은
`2ea293aa20ba7cf5bbf3ba17a5fbcb1a01cbfe21`입니다.

세트마다 독립 검색 시드 3개를 사용하고, 각 시드에서 방법별 4회 실행합니다.
처음 2개 환경은 공통 Uniform bootstrap으로 양 방법에서 **별도 실행**합니다.
다음 2회는 AFS가 자신의 해당 태스크·세트·시드 AFS 결과로 제안하고, Random은 전체
공유 범위의 각 변수를 독립 Uniform으로 뽑습니다. 과거 실험, Random, 다른 태스크나
다른 시드의 결과를 AFS에 전달하지 않습니다. 18개 검색 시드는 결과를 보기 전에
SystemRandom으로 한 번만 추출했으며 기하나 결과에 따라 교체하지 않았습니다.

## 태스크별 추가한 실패 환경

아래는 실패를 찾기 위한 **환경 가설**입니다. 이 설계만으로 실제 실패 원인이나
실패 유형을 확정하지 않습니다. 모든 변수는 AFS와 Random에 같은 범위를 적용합니다.
두 방법 모두 모든 축을 선택하며, 특정 유형을 강제로 몇 회 채우는 할당은 없습니다.

### Object: 14개 축

| 환경 변수 | 범위 | 살펴볼 동작 |
|---|---|---|
| 버터 X / Y | −17~−11cm / −27~−21cm | 접근 위치 변화 |
| 버터 yaw | −180~180° | 파지 방향 변화 |
| 버터 질량 배율 | 기본의 0.5~3배 | 물체 하중 변화 |
| 버터 접촉면 sliding friction | 0.25~1.2 | 접촉 특성 변화 |
| 바구니 X / Y | −3.5~3.5cm / 25~32cm | 운반 경로·목표 접근 변화 |
| 바구니 yaw | −30~30° | 목표 진입 방향 변화 |
| 정적 상자 X / Y | −6~−2cm / 1.5~5.5cm | 운반 경로 주변 차단 |
| 상자 전체 폭 / 깊이 / 높이 | 2~6cm / 2~6cm / 3~18cm | 차단 형상 변화 |
| 상자 yaw | −90~90° | 비스듬한 차단 |

좌표는 월드 XY이며 원래 Object 장면의 바닥을 사용합니다. 상자는 바닥 z=0에 접합니다.
버터·바구니 Z는 원래 reset 값을 보존하며 yaw만 월드 Z축으로 설정합니다.
버터 질량 변경은 XML의 해당 물체 density에 적용해 관성도 함께 변하게 합니다.
마찰 변경은 버터 표면의 sliding 성분이며 로봇 그리퍼·제어기는 바꾸지 않습니다.

### Goal: 11개 축

| 환경 변수 | 범위 | 살펴볼 동작 |
|---|---|---|
| 캐비닛 X / Y | 1.5~6.5cm / −28~−24cm | 손잡이 접근 위치 변화 |
| 캐비닛 yaw 변화 | 기본 180°에서 ±약 8.6° | 손잡이 접근 각도 변화 |
| 가운데 서랍 damping 배율 | 기본 50의 0.5~4배 | 속도에 따른 서랍 저항 변화 |
| 가운데 서랍 frictionloss | 0~4N | 서랍 관절의 건조 마찰 변화 |
| 상자 lateral / forward | 2~8cm / 16~22cm | 손잡이 접근·서랍 이동 공간 차단 |
| 상자 전체 폭 / 깊이 / 높이 | 2~5cm / 2~4.5cm / 4~16cm | 차단 형상 변화 |
| 상자 yaw | 캐비닛 변화 방향에서 ±90° | 비스듬한 차단 |

상자 lateral/forward는 캐비닛 원점 기준으로, 기본 outward 방향인 월드 +Y를 사용하고
캐비닛 yaw 변화에 따라 함께 회전합니다. 상자는 기존 테이블 z=0.9에 접합니다.
가운데 서랍은 닫힌 q=0에서 시작하며 native 관절 range와 Open 성공 판정은 유지합니다.
기존 접시 하나는 장애물의 초기 관통을 피하도록 [25cm, 8cm]에 고정하며 두 방법에 같습니다.
이 변경으로 기본 환경의 예전 PASS가 새 환경의 PASS를 보증하지는 않습니다.

초기 유효성은 물리적 달성 가능성이나 실패를 보장하지 않습니다. 장애물 때문에 작업이
막힌 경우도 이 환경 범위의 결과입니다. 로봇 자체의 기구학적 한계를 입증하는 실험으로
해석하지 않습니다.

## 판정·측정·중단

원래 LIBERO `check_success`로 PASS/FAIL을 정합니다. 접촉이나 움직임 휴리스틱으로
FAIL을 만들지 않습니다. 초기 관통, 경계 이탈, 이미 성공한 초기 상태, API·스키마·실행
오류는 제외 또는 미완료이며 로봇 FAIL에 합산하지 않습니다. 정적 상자와 고정 캐비닛
사이도 직접 geom distance로 검사해 static-static contact 필터에 의존하지 않습니다.

초기 배치/XML/전체 sim state, 네이티브 결과, 영상, control trace와 매 physics step의
물체·서랍 상태 및 접촉 시간 측정을 저장합니다. Object는 안정화 1초 뒤 움직임과
바구니 근접을, Goal은 서랍의 이동량을 설명용 패턴으로 기록합니다. 잡기 성공·떨어뜨림·
실패 원인으로 확정하지 않으며 불완전 물리 기록은 UNKNOWN입니다.

각 요청/실행 전에 intent를 저장합니다. 응답 없는 API intent나 결과 없는 로봇 intent는
재전송하지 않습니다. 유효한 완료 결과만 건너뛰어 이어가며 제외된 슬롯은 교체하지 않습니다.
한 세트의 오류는 그 세트를 멈추고 다른 독립 세트는 계속하며, 최종 종료 코드는 모든 세트가
완료되지 않으면 비정상입니다. 사용자 인터럽트는 전체 배치를 중단합니다.

## 결과 위치와 실패율

출력 루트: `experiments/robot_arm_libero/object_goal_search_repetitions3_v1`.
개별 에피소드: `<task>/set_<n>/seed_<seed>/<afs|random>/attempt_<index>`.
실패 영상은 `receipt.json`이 VALID/FAIL인 에피소드의 `videos/` 아래에 있습니다.

루트 `replication_summary.json`과 `.txt`에서 태스크별/세트별 PASS·FAIL·제외·미완료,
고유 실패 환경·재확인 실패, 관측 패턴, AFS 요청·알려진 토큰 사용량을 확인합니다.
실패율은 **native FAIL / 유효 에피소드 수**이며 할당 슬롯당 발견률도 별도로 남깁니다.
각 태스크의 3세트가 전부 완료된 후에만 세트별 실패율의 평균과 표본 표준편차,
AFS−Random 차이(%p)를 계산합니다. 일부 완료 세트만 골라 평균을 내지 않습니다.
Bootstrap과 후반 선택의 실패 수도 분리합니다. 반복된 실패 환경은 새로운 유형으로 세지
않습니다. AFS는 추가 API 비용을 쓰므로 같은 rollout 수가 같은 총비용을 뜻하지 않습니다.

이는 개발 중 정한 두 태스크의 환경 범위에 대한 작은 반복 비교입니다. 태스크별 결과를
따로 보고하며 전체 LIBERO 성공률이나 통계적 우월성을 자동으로 주장하지 않습니다.

## 준비 단계의 검증

고정한 예정 Uniform 배치 72개(Object 36, Goal 36)가 네이티브 CPU 기하 검사를 모두
통과했습니다. 후보·시드를 교체하거나 재추출하지 않았습니다. 초기 검사 v1의 경계 구
과대 추정 결과는 보존했고, 실제 회전 box AABB를 쓰는 최종 v2 검사로 같은 후보들을
확인했습니다. 최종 기록은 `development/object_goal_geometry_20261024_v2/geometry_audit.json`입니다.
미래 AFS 제안의 유효성이나 실제 로봇 성공률을 보장하는 검사는 아닙니다.

관련 모의·회귀 검사 86개가 통과했습니다. 별도 네이티브 CPU 검사는 정책·카메라를
테스트 대역으로 바꾸고 실제 LIBERO에서 태스크별 1 control step을 실행해 환경 적용,
종료 시 중복 reset 방지, 전체 physics 기록 연결을 확인했습니다. 이는 실제 정책 실행
결과로 집계하지 않습니다. Ruff와 Bash 문법 검사도 통과했습니다.
