# 휴머노이드 전체 범위 개발 실험

기존 navigation 비교(AFS 0/18 FAIL, Random 2/18 FAIL)는 보존한다.
이번 준비는 좁아진 탐색 영역을 재검토하기 위한 개발 실험이며 AFS 우월성
평가나 기존 실험의 재개가 아니다. 아직 실제 로봇 결과는 없다.

통로 폭을 원래 범위의 세 구간으로 나눈다. 숫자 구간과 seed는 새 rollout
결과를 보기 전에 고정한다. 난이도 순서를 증명한 구간은 아니다.

| 구간 | 폭(m) | seed | 유효 목표 / 시도 상한 |
|---|---|---|---|
| narrow | 1.6–2.4 | 62001 | 4 / 4 |
| middle | 2.4–3.2 | 62002 | 4 / 4 |
| wide | 3.2–4.0 | 62003 | 4 / 4 |

나머지 19개 축은 `clear-path-human-v5`의 원래 범위다. 특히 바닥 마찰은
0.05–1.5, 상자 횡위치는 −1–1로 복원한다. 세 직사각형 영역의 합집합은
원래 20축 전체 영역이다. 실제 12개 표본이 모든 조합을 덮는다는 뜻은 아니다.
새 지형·물체 수·과제·정책을 추가하는 실험도 아니다.

Luna/default, 에피소드당 최대 10회 정책 호출, 목표·체류·push 조건은 검증된
clear-goal control 두 결과에서 동일하게 가져온다. 두 결과 모두 사용하며
평가 이력으로 가져오지는 않는다. 총 12시도/최대 120로봇 정책 호출/0 AFS다.
제외가 발생하면 기존 실행기가 중단하며, 대체·자동 재시도·예산 초기화가 없다.

오프라인 준비:

```bash
uv run --no-sync python tools/prepare_humanoid_broad_development.py \
  --output-dir development/humanoid_broad_20261022_v1 \
  --run /workspace/g1_failure/runtime/goal_clearance_control/luna_clear_goal_20261021_v1/attempts/attempt_00000/rollout \
  --run /workspace/g1_failure/runtime/goal_clearance_control/luna_clear_goal_20261021_v1/attempts/attempt_00001/rollout
```

기존 출력 폴더는 덮어쓰지 않는다. 출력에는 구간별 config, 소스·리소스 해시를
포함한 plan, 실제 실행기가 사용할 동일 seed/index의 장면 12개와 초기 상자
기하 진단이 포함된다. 준비 도구는 캠페인 실행이나 DB 열기를 하지 않는다.
plan은 준비 시점의 증거이며 실행 직전에는 기존 CLI의 새 init/freeze가 필요하다.

목표 주변이 막힌 장면도 제거하거나 다시 뽑지 않는다. 초기 상자 투영과
보수적인 endpoint 반경 0.4m, 목표 반경 0.25m로 공통 병목의 충분조건을
기록한다. 이는 경로 검사·물리적 불가능성·실패 판정이 아니다. 움직일 수 있는
상자를 조작하거나 다른 행동으로 성공할 가능성은 남는다.

실제 결과는 구간별 PASS/FAIL/제외, 실패 분류, 경로·행동·진행량, 호출 비용과
함께 검토한다. FAIL을 마찰·폭의 원인으로 바로 단정하지 않는다. 여러 축이 함께
변하므로 인과 분리가 필요하면 별도 대조 실험을 설계한다. 12개 개발 표본으로
실패율을 보장하거나 seed를 결과에 맞춰 바꾸지 않는다. 이후 AFS/Random 비교는
동일 공통 영역과 새 평가 seed를 명시적으로 고정한 별도 실험으로 준비한다.

## 이번 오프라인 결과

12/12 장면의 스키마·범위 검증과 세 계획의 실제 증거/소스/리소스 검증이
완료됐다. 목표 영역 전체가 상자의 보수적 endpoint envelope 안에 들어간다는
충분조건은 narrow 4/4, middle 4/4, wide 2/4, 합계 10/12였다. 탈락·재추출은
0회다. 이는 실제 실패 10건이라는 뜻이 아니다.

따라서 이 준비만으로 다양한 실패 탐색 문제가 해결됐다고 보지 않는다.
다음 설계에서는 통로·마찰·장애물 범위를 넓게 유지하면서 목표 부근 상자의
배치를 독립적으로 제어할 수 있는지 검토하는 것이 우선이다. 현재는 상자 X가
6.8–7.5m로 목표 X=7m 부근에 묶여 있다. 이를 변경하려면 기존 물리 스키마의
새 버전과 공통 영역을 명시적으로 도입해야 하며, 검사·목표 판정을 약화하거나
유리한 장면만 재추출하는 방식으로 해결하지 않는다. 유료 실행은 하지 않았다.
