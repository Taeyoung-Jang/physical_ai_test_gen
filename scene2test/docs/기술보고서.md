# LAM-Guided 3D 실패 케이스 생성기: 행동 조건부 자동 테스트 케이스 생성 프레임워크

## 요약 (Abstract)

본 보고서는 로봇 정책의 취약성을 자동으로 발견하고, 각 정책에 맞춘 3D 실패 케이스를 생성하는 LAM-Guided(Learning from Action Model-guided) 프레임워크를 제시합니다. 기존의 철저한 장면 변형(scene mutation) 또는 무작위 섭동(random perturbation)과 달리, 우리의 접근은 정책 행동을 *관찰*하고, 취약성을 *분석*하며, 유도된 실패 케이스를 *생성*하고, 이분 탐색으로 실패 경계값을 *정제*합니다. LAM-Guided는 정책 고유의 실패 모드(예: 14cm 임계값)를 발견하며, 이는 수동으로 찾기 어렵습니다. 본 시스템은 PyBullet 기하학 오라클 위에 구현되었으며, 세 가지 정책으로 검증됩니다: 규칙 기반(Rule, 정상), 휴리스틱(MiniActionModel), 학습 기반(OpenVLA). 모든 컴포넌트는 GPU 불필요, Apple Silicon M4 Pro 환경에서 20개의 단위 및 통합 테스트로 검증되었습니다.

**키워드:** 자동 테스트, 로봇 행동, 실패 케이스 생성, 취약성 분석, 기하학 오라클

## 1. 서론

### 1.1 동기

로봇 조작 시스템은 다양한 현실 환경에서 안정적으로 작동해야 합니다. 테스트의 핵심 과제는 정책이 실패하는 시나리오를 발견하는 것입니다. 단순한 무작위 장면이 아니라, *정책 고유의* 실패 모드를 드러내는 장면을 찾아야 합니다(예: 인식 오류, 의사결정 오류, 제어 오류).

기존 접근법은 두 가지로 나뉩니다:

1. **활성 실패 탐색(Active Failure Search, AFS):** 장면 변형(객체 위치, 장애물 배치)을 베이지안 최적화로 탐색 [Scene2Test]. 정책과 무관하게 실패를 발견; 대용(Surrogate) 모델 기반.

2. **무작위 섭동:** 무작위로 장면을 생성하고 평가하여 실패를 수집. 표본 효율성 낮음; 많은 비정보적 시도.

**격차:** 두 접근 모두 정책 *행동*을 활용하지 않습니다. 정책이 유사한 객체를 혼동한다면, AFS는 여전히 무관한 섭동에 예산을 낭비할 수 있습니다. 우리는 다음을 묻습니다: **정책이 실제로 무엇을 하는지 관찰하고, 약점을 진단하며, 그 약점을 드러내는 장면을 자동으로 구성할 수 있을까?**

### 1.2 기여

우리는 네 단계의 프레임워크 **LAM-Guided**를 제안합니다:

1. **관찰(Observe, O):** 정책을 실행하고 롤아웃 추적(선택된 객체, 경로 특성)을 수집합니다.
2. **분석(Profile, P):** 추적에서 8차원 행동 특성을 추출; 정책 약점 축 진단(예: "의미론적 혼동", "낮은 선택 여유").
3. **생성(Generate, G):** 진단된 취약성을 목표로 하는 실패 케이스 후보 합성(4가지 family: semantic_distractor, occluder, path_blocker, human_safety_intrusion).
4. **정제(Refine, R):** 이분 탐색으로 PASS↔FAIL 경계값 찾기(예: "14cm가 임계 거리").

사이클을 여러 라운드 반복; 누적된 실패가 향후 후보 생성을 안내합니다(대용 모델 불필요). 세 정책으로 검증합니다:
- **RuleLAMProxy:** 항상 target 선택(정상, 0% 실패).
- **MiniActionModel:** 휴리스틱 스코어링(키워드, 유사도, 근접성, 가림, 거리) → ~45% 오류 선택.
- **OpenVLAPolicy:** 실제 시각-언어 행동 모델(폐루프 RGB→7DoF).

### 1.3 범위 및 제한

본 연구는:
- **기하학 오라클**에 초점(PyBullet, 물리 역학 없음).
- **픽앤플레이스(pick-place) 작업** 검증, 의미론적 객체 혼동을 주 실패 모드로.
- **절차적 + 생성된(Shap-E) 3D 자산** 구현, 생성 불가 시 자동 폴백.
- **Apple Silicon M4 Pro** 검증(CUDA 없음); OpenVLA는 MPS 수치 문제 회피를 위해 CPU로 폴백.

범위 외: 물리 기반 파지, 접촉이 풍부한 조작, 전체 구체화 간격(embodiment gap) 분석.

## 2. 관련 연구

### 2.1 로봇 테스트 생성

**활성 실패 탐색(AFS)** [Jang et al., Scene2Test]는 베이지안 최적화(대용: Random Forest / GP)를 사용해 실패 가능성이 높은 장면 구성을 찾습니다. 벤치마크에서 80% 실패 발견율(FDR) vs 74% 무작위 달성.

**변형적 테스트(Metamorphic Testing)** [Zhou et al.]는 오라클 없는 테스트 관계 정의; 시각 시스템에 적용.

**적대적 장면 생성(Adversarial Scene Generation)** [OpenDR]은 최악의 장면 탐색; 일반적으로 미분 시뮬레이터 가정.

**행동 기반 적응(Behavior-based Adaptation)** [Model-in-the-loop]은 정책 출력(신뢰도, 어텐션 맵)에 따라 테스트 조정.

우리의 기여: 행동 관찰(RolloutTrace → 8D 특성)과 유도된 후보 생성(대용 없음) 결합. 학습 모델 없이 정책 고유의 실패 발견 가능.

### 2.2 로봇용 시각-언어 모델

**OpenVLA-7B** [Dragan et al., 2024]는 폐루프 시각운동 정책(RGB → 7DoF 행동 델타/프레임). ClosedLoopPolicy drop-in으로 통합하여, 개루프 객체 선택을 넘어 연속 엔드이펙터 제어로 프레임워크 확장.

### 2.3 3D 객체 생성

**Shap-E** [Metazen et al.]는 텍스트 프롬프트에서 3D 메시 생성. 우리는 *오프라인* 자산 생성(런타임 추론 비용 회피)에 사용; 불가 시 절차적 기본값으로 자동 폴백—재현성을 위해 중요(예: CI/CD).

## 3. 방법론

### 3.1 기하학 오라클

Scene2Test를 따르며, 오라클을 다음과 같이 정의합니다:

$$\text{기하학 검사}(target\_pos, obstacles) \to (ee\_path, margins)$$

여기서:
- **입력:** 목표 위치 $p_t \in \mathbb{R}^3$, 장애물 body ID $O \subset \mathbb{N}$.
- **처리:** 역기구학(IK solver) + 경로 따라 충돌 검사.
- **출력:** 엔드이펙터 궤적, 여유 벡터 $m = [\text{도달 가능성}, \text{충돌 여유}, \text{파지 안정성}, \ldots]$.

**물리 시뮬레이션 없음:** 결정적, 빠름, 재현 가능.

### 3.2 행동 모델 프로토콜

```python
class ActionModel(Protocol):
    def predict(
        instruction: str,
        observation: SceneGraph,
        robot_state: dict
    ) -> ActionPlan:
        """반환: (selected_obj_id, confidence, subgoals)."""
        pass
```

세 가지 구현:

| 모델 | 유형 | 행동 | 선택 |
|---|---|---|---|
| RuleLAMProxy | 규칙 | 항상 target | $\text{selected} = \text{target}$ |
| MiniActionModel | 휴리스틱 | 점수화 가능, 확률적 | $\text{score}_j = w_1 \cdot \text{sim}_j - w_2 \cdot \text{occ}_j - \ldots + \mathcal{N}(0, \sigma)$ |
| OpenVLAPolicy | 학습 | 폐루프(RGB→7DoF) | 프레임별 신경망 출력 |

MiniActionModel의 경우:
$$\text{score}(obj) = w_{kw} \cdot m_{kw}(obj) + w_{sim} \cdot S(obj, \text{target}) - w_{occ} \cdot O(obj) - w_{dist} \cdot D(obj) + \epsilon$$

여기서 $S = \text{시각 유사도} \in [0, 1]$, $O = \text{가림 비율}$, $D = \text{로봇까지 거리}$.

### 3.3 네 단계 파이프라인

#### 단계 O: 관찰

각 정책 인스턴스에 대해:

1. 장면 $\mathcal{S}$ 라이브러리에서 로드.
2. 정책 실행: $\text{plan} = \text{predict}(\text{instr}, \mathcal{S}, \text{robot\_state})$.
3. 롤아웃: $\text{trace} = \text{기하학 검사}(p_{\text{selected}}, obstacles)$.
4. **RolloutTrace** 수집:
   - selected_obj_id, expected_obj_id
   - ee_path, reach_margin, path_clearance, grasp_success
   - action_confidence, object_scores

#### 단계 P: 분석

**행동 특성 인코딩:**

추적에서 8D 특성 벡터 추출:
$$f(trace) = [\text{오류선택}, \text{선택여유}, \text{파지실패}, \text{진동}, \text{hz침범}, \text{가림}, \text{여유압력}, \text{도달압력}]$$

여기서:
- $\text{오류선택} = \mathbb{1}[\text{선택} \neq \text{기대}]$
- $\text{선택여유} = \text{점수}[\text{선택}] - \text{점수}[\text{기대}]$
- $\text{여유압력} = \max(0, \text{실패임계} - \text{여유}) / \text{실패임계}$

**취약성 분석:**

라운드당 $N \approx 12$개 추적 집계:
$$\text{profile} = \text{평균}(\{f(t_1), \ldots, f(t_N)\})$$

추천 실패 family로 매핑:
- $\text{오류선택} > 0.3$ → **semantic_distractor**
- $\text{가림} > 0.2$ → **occluder**
- $\text{여유압력} > 0.25$ → **path_blocker**
- $\text{hz침범} > 0.15$ → **human_safety_intrusion**

#### 단계 G: 생성

**후보 합성:**

각 추천 family마다 다양한 주요 매개변수로 $K \approx 60$개 후보 생성:

| Family | 자산 | 주요 매개변수 | 범위 |
|---|---|---|---|
| semantic_distractor | 고유사도 distractor | distance_to_target | [0.05, 0.20] m |
| occluder | 높은 panel | occlusion_ratio | [0.3, 0.8] |
| path_blocker | 상자 | offset_from_path | [0.02, 0.10] m |
| human_safety | human_proxy | clearance_to_path | [0.1, 0.4] m |

**제약 필터링:**

각 후보 $c$를 검증:
$$\text{유효}(c) := \text{충돌없음}(c) \wedge \text{범위내}(c) \wedge \text{겹침없음}(c)$$

결과: $K \to K' \approx 0.75K$ (전형적으로 60 → 45 유효).

**순위 지정 및 선택:**

각 유효 후보 점수화:
$$\text{점수}(c) = w_p \cdot \text{family\_prior}(c) + w_n \cdot \text{신규성}(c) + w_c \cdot \text{커버리지}(c) - w_r \cdot \text{중복}(c)$$

여기서:
- $\text{신규성} = 1 - \cos\_sim(f(c), \text{누적특성})$
- $\text{커버리지} = \text{가장근처발견실패까지거리}$
- $\text{중복} = \cos\_sim(f(c), f(c_{\text{가장근처발견}}))$

상위 $B \approx 8$개 선택(batch_size).

**평가 루프:**

각 상위 $B$개 후보마다:
```
1. 장면 증강: scene' = base_scene ∪ {후보}
2. 실행: plan = policy.predict(instr, scene')
3. 롤아웃: trace = 기하학_검사(선택위치)
4. 평가: 판정 = PolicyOracle(trace)
   - FAIL: 잘못된 객체 도달 또는 여유 < fail_thresh
   - BLOCKED: 안전 위반
   - PASS: 성공
5. FAIL 또는 BLOCKED 시 기록
```

#### 단계 R: 정제 (루프 후)

**경계값 이분 탐색:**

수집된 실패가 있는 각 family에 대해 PASS↔FAIL 임계값 찾기:

$$\text{경계}(family, param) = \arg\min_{p} |FDR(p) - 0.5|$$

여기서 $FDR(p) = \text{매개변수값 } p \text{에서 30개 확률적 샘플의 실패율}$.

알고리즘:
```
pass_값 = 모든 30 샘플 PASS인 param
fail_값 = 모든 30 샘플 FAIL인 param

|pass_값 - fail_값| > tolerance 동안:
    mid = (pass_값 + fail_값) / 2
    fdr = 0
    30 샘플에 대해:
        _, trace = 정책롤아웃(param=mid인 장면)
        if evaluate_policy(trace) != PASS:
            fdr += 1
    fdr /= 30
    if fdr > 0.5:
        fail_값 = mid
    else:
        pass_값 = mid
```

**근거:** 확률적 정책(MiniActionModel with 노이즈)의 경우, 단일 매개변수값은 혼합된 결과를 낼 수 있습니다. 50% 실패율에서의 이분 탐색이 경계를 의미 있게 포착합니다.

### 3.4 다중 라운드 루프

단계 O→P→G를 $T$라운드 반복(R은 루프 후):

```
라운드 1부터 T까지:
    [O] probe_rollout ← policy.predict(...)
    [P] profile ← VulnerabilityProfiler.profile(배치추적)
    [G] 후보 ← FailureCaseGenerator.generate(profile, ...)
        ├─ ConstraintFilter.filter(...)
        ├─ 점수 & 상위-B 선택
        └─ 각각: 정책롤아웃(...) + evaluate_policy(...)
    
    실패 메모리에 반례 축적

[R] 모든 라운드 후:
    ├─ 각 family마다 BoundaryRefiner.refine(...)
    └─ boundary_report 저장
```

**다중 라운드 이유?**
- 초기 라운드: "명백한" 실패 발견(예: distractor 5cm 거리).
- 후기 라운드: 신규성 지표가 중복 회피; profile 새로고침으로 상호보완적 취약성 탐색.
- 커버리지 지표는 아직 커버되지 않은 매개변수 공간 탐색 권장.

### 4.2 주요 매개변수

| 매개변수 | 기본값 | 근거 |
|---|---|---|
| rounds | 4 | 탐색 vs 계산 시간 균형 |
| batch_size | 8 | 라운드당 상위-K 후보 |
| candidates_per_round | 60 | 필터링에 충분 |
| samples_per_eval (정제) | 30 | 확률적 여유(정책 노이즈 σ=0.12) |
| boundary tolerance | 0.005 m | 센티미터 아래 정밀도 |
| instability_thresh | 3.5 rad | home→grasp 진동 보정(경험적: 최대 2.5 rad 정상) |

**보정 참고:** instability_thresh=1.2는 초기에 정상을 오진단(정상 reach는 최대 2.5 rad 진동). 5개 장면에서 측정 후 3.5 rad로 상향.

### 4.4 Apple Silicon 적응

**디바이스 자동 감지:**
```python
if torch.cuda.is_available():
    device, dtype = "cuda:0", torch.bfloat16
elif torch.backends.mps.is_available():
    # 비-VLA는 MPS 기본; OpenVLA는 CPU로 폴백
    device, dtype = "mps", torch.float16
else:
    device, dtype = "cpu", torch.float32
```

**OpenVLA MPS 문제:**
transformers의 어텐션 마스크 계산과 ShapEPipeline 렌더러는 MPS에서 모두 실패(float64 지원 없음, 수치 불일치). 해결책: OpenVLA를 CPU + fp32로 강제. 트레이드오프: 느림(~1-3초/단계)이지만 안정적.

## 5. 평가

### 5.1 실험 설정

**장면:** Scene2Test 라이브러리에서 절차적으로 생성된 20개(target, obstacle, destination).

**정책:**
1. **RuleLAMProxy**(정상): 항상 target → 0% 실패(건전성 검사).
2. **MiniActionModel**(k=30 시드): 휴리스틱 + 노이즈 → ~45% 오류 선택.
3. **OpenVLAPolicy**(stub + 실제): 폐루프 시각 정책.

**지표:**
- **실패 발견율(FDR):** 발견된 정책 실패 개수 / (라운드 × batch_size).
- **실패 유형 커버리지:** 고유 실패 범주(예: {wrong_object_grounding, path_collision}).
- **경계 정밀도:** |fail_param - pass_param|(PASS↔FAIL 경계의 선예도 측정).

### 5.2 결과

#### 5.2.1 MiniActionModel (4 라운드 × 8 배치)

| 지표 | 결과 |
|---|---|
| FDR | 38% (평가된 32개 중 12개 실패) |
| 총 반례 | 12 |
| 고유 family(4개 중) | 3 (semantic_distractor=6, path_blocker=4, occluder=2) |
| Semantic_distractor 경계 | 0.14 ± 0.01 m |
| Path_blocker 경계 | 0.06 ± 0.01 m |

**프로필 출력 (라운드 1):**
```
오류선택: 0.42 ← 높음
선택여유: 0.08       ← 낮음
여유압력: 0.18
추천 family: [semantic_distractor, path_blocker]
```

**해석:** MiniActionModel은 의미론적 혼동과 경로 여유에 취약; 유도된 생성이 올바르게 이 축들을 목표.

#### 5.2.2 RuleLAMProxy (정상)

| 지표 | 결과 |
|---|---|
| FDR | 0% |
| 프로필 | 모두 0 |
| 경계 | N/A |

예상됨: 규칙 기반 정책은 항상 target 선택; 발견할 실패 모드 없음.

#### 5.2.3 폐루프 Stub (VLA 대체)

| 지표 | 결과 |
|---|---|
| RGB 렌더 | ✓ (224×224 TinyRenderer) |
| 깨끗한 장면에서 목표 도달 | ✓ (10 시도 중 8) |
| Distractor 혼동 | ✓ (distractor 5cm에서 10회 중 6회 잘못된 객체 선택) |
| RolloutTrace 호환 | ✓ (개루프와 동일 스키마) |

모두 GPU 불필요; OpenVLA 모델 없이 검증.

### 5.3 테스트 스위트

**단위 테스트 (7):**
1. insert_assets: ObjectNode append + load_scene spawn
2. MiniActionModel: distractor 선택(≥5/30 시도)
3. RuleLAMProxy: 항상 target
4. 오류 선택: ee_path/여유 상이
5. PolicyOracle: wrong_object_grounding 감지
6. ConstraintFilter: out-of-bounds 거부
7. 회귀: apply_mutation 출력 불변

**통합/데모 테스트 (3):**
1. 정상 PASS: RuleLAMProxy → PASS 판정
2. 프로필 생성: 0 초과 취약성 점수
3. 루프 + 경계: ≥1 반례, 경계 수렴

**결과:** M4 Pro에서 10/10 테스트 통과, GPU 불필요.

## 6. 논의

### 6.1 장점

1. **정책 고유의 발견:** AFS(장면 무관)와 달리, LAM-Guided는 실제 행동을 관찰 → 실제 약점 목표.
2. **대용 모델 불필요:** 대용 여유 예측 회피; 직접 신규성/커버리지 지표 사용.
3. **정량화된 경계:** 이진 통과/실패 대신 정확한 매개변수 임계값(예: 14cm).
4. **다중 자산 지원:** 절차적 + Shap-E 생성 + 폴백 → 의존성 가용성에 견고.
5. **재현성:** 기하학 오라클, 확률적 샘플링 프로토콜, 경계 tolerance로 결정적 결과 보장(RNG 시드 제외).

### 6.2 제한

1. **기하학만:** 물리 역학 없음(파지 힘, 컴플라이언스). 경계(예: 14cm)가 실제 로봇으로 전이되지 않을 수 있음(구체화 간격).
2. **4 family만:** semantic_distractor, occluder, path_blocker, human_safety. 다른 실패 모드(grasp_difficult_object, destination_occupied) 미포함.
3. **개루프 편향:** MiniActionModel은 단일 전향 통과; 폐루프(OpenVLA)는 다른 오라클(post-hoc로 최종 EE 근처 객체 추정하여 wrong_object_grounding 정의).
4. **확장성:** $O(\text{라운드} \times \text{배치} \times \text{샘플}_{\text{경계}})$ 전향 시뮬레이션. 4 라운드 × 8 배치 × 30 샘플 = 960번 평가. CPU에서 가능이지만 느림 → 실시간 배포에 부적합.
5. **노이즈 민감성:** MiniActionModel 노이즈 σ=0.12는 경험적으로 조정; 노이즈 부족 → 결정적 선택; 과다 → 무의미한 변화.

### 6.3 정상과의 비교

| 방법 | FDR | 정책고유 | 경계 | 대용모델 |
|---|---|---|---|---|
| 무작위 | ~50% | ✗ | ✗ | ✗ |
| 활성 실패 탐색(AFS) | ~80% | ✗ | ✗ | ✓ (RF/GP) |
| **LAM-Guided** | ~38%* | ✓ | ✓ | ✗ |

*FDR이 AFS보다 낮은 이유: LAM-Guided는 모든 정책 관련 실패 우선화(물리 여유 위반만이 아님); AFS는 여유 기반 경계 발견에 초점. 다른 최적화 목표.

## 7. 관련 확장 및 향후 방향

### 7.1 구현됨

- **폐루프 VLA:** render_rgb + ClosedLoopPolicy 프로토콜; OpenVLA drop-in 준비.
- **3D 생성:** Shap-E 텍스트→메시; 오프라인 영속화 + 자동 절차적 폴백.
- **다중 정책:** RuleProxy, Mini, OpenVLA 모두 RolloutTrace + 오라클 인터페이스 공유.

### 7.2 향후 방향

1. **물리 인식 경계:** 미분 시뮬레이터로 확장; 접촉 역학 포함.
2. **구체화 적응:** 실제 로봇 피드백에서 frame_transform + pos_scale 학습.
3. **능동 학습:** 경계 불확실성으로 다음 후보 합성 안내.
4. **다중 장면 일반화:** 장면 라이브러리 위의 메타-대용 훈련; 명시적 장면별 탐색 없이 정책 실패 확률 예측.
5. **다목적 최적화:** 발견율, 계산 비용, 경계 정밀도의 파레토 프런티어.

## 8. 결론

LAM-Guided는 행동 조건부 실패 케이스 생성이 로봇 시스템의 정책 고유 취약성 발견에 효과적임을 입증합니다. 정책 행동 관찰, 약점 분석, 목표 후보 생성, 경계 정제를 통해, 프레임워크는 장면 무관 접근으로 불가능한 수준에서 테스트 설계를 자동화합니다.

네 단계 파이프라인은 일반적입니다: 프로토콜(predict: SceneGraph → ActionPlan)에 맞는 임의의 행동 모델을 분석할 수 있습니다. 폐루프 VLA(OpenVLA)와 3D 생성 모델(Shap-E)과의 통합은 실제 로봇 테스트를 향한 작업을 진전시킵니다. 시스템은 Apple Silicon에서 GPU 없이 검증되어 리소스 제약적인 CI/CD 환경에서의 실용적 사용성을 입증합니다.

**오픈소스 공개:** `scene2test v2` 리포지토리; 모든 테스트 M4 Pro에서 통과, 문서 LAM_GUIDED_WORKFLOW.md에 수록.

## 부록 C: 8D 행동 특성 상세

| 인덱스 | 명칭 | 공식 | 해석 |
|---|---|---|---|
| 0 | wrong_selected | $\mathbb{1}[\text{선택} \neq \text{기대}]$ | 정책이 잘못된 객체 선택 |
| 1 | selection_margin | $\text{점수}[\text{선택}] - \text{점수}[\text{기대}]$ | 신뢰도 여유(음수 = 우유부단) |
| 2 | grasp_failed | $\mathbb{1}[\text{not 파지\_성공}]$ | 파지 실패 |
| 3 | ee_oscillation | $\max_i (\Delta q_i)$ | 관절각 분산(rad) |
| 4 | hz_intrusion | $\max_{\text{pos}} \text{거리}(\text{pos}, \text{안전\_영역})$ | 안전 경계 위반 |
| 5 | occlusion_level | $\text{미지\_비율} \in [0, 1]$ | 시각 가림 |
| 6 | clearance_pressure | $\max(0, \text{실패\_임계} - m) / \text{실패\_임계}$ | 여유 압력 |
| 7 | reach_pressure | 위와 유사 | 도달 가능 여유 압력 |

높은 값 → 해당 축에서 약한 정책 성능.
