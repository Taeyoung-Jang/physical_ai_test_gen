# Luna 소규모 실험과 AFS 장면 확장 계획

2026-09-28 UTC. Luna 설정/로컬 검증과 앞으로 구현할 장면 확장을 구분한다.
기존 Astra 결과를 수정하거나 재분류하지 않는다.

## 1. 모델 변경 범위와 실행

사용자의 비용 절감 요청에 따라 `config/behavior_afs_luna_smoke.json`은
**로봇 VLM과 AFS 제안자 모두 `gpt-6-luna`**로 지정한다.
[공식 모델 문서](https://developers.openai.com/api/docs/models/gpt-6-luna)는
이미지 입력, Responses API, Structured Outputs, 현재 쓰는 reasoning 수준을 지원한다고 명시한다.
이 호환성은 해당 계정의 접근 권한이나 실제 로봇 성능 검증을 대신하지 않는다.

| 조건 | 이번 설정 |
|---|---|
| seed / domain | 17 / 기존 질량·상자 마찰·바닥 마찰 전체 공간 |
| 예산 | AFS 3회 + Random 3회 유효 실행 목표, 각 방법 총 시도 최대 3회 |
| cold start | 방법별 2회, 같은 장면을 별도로 실행·과금 |
| 이후 실행 | AFS LLM 제안 1회에 따른 장면, Random 전체 공간 표본 1회 |
| API 상한 | 로봇 최대 60회, AFS 최대 1회; 자동 재시도 없음 |
| episode 조건 | 로봇 10회 호출, HTTP read 300초, 시뮬레이션 기본 시간 상한 없음 |
| 평가/로봇 | goal_outcome_v1, 기존 영상·GT 지도·내부 계획기·CUDA 보행·실험적 push |

API endpoint, 프롬프트, 출력 schema, reasoning 설정, 출력 토큰 상한, 관측 조건,
물리 실행기와 episode 예산은 바꾸지 않는다. 전략 목록은 기존대로 유지하지만
이번 3회 예산으로는 전체 boundary/exploration/repeat 순서를 실행하지 않는다.
오류가 생기면 중단하며 자동 추가 시도 예산이 없으므로 미완료가 될 수 있다.
모델·실행 규모를 바꾼 연결 점검이지, 기존 Astra 캠페인과의 정식 성능 비교는 아니다.

프로젝트의 `scene2test` 디렉터리에서, README에 따라 키를 설정한 같은 터미널에서 실행한다.

```bash
uv run --no-sync python tools/run_afs_pilot.py --config config/behavior_afs_luna_smoke.json
```

```bash
uv run --no-sync python tools/run_afs_pilot.py --live --config config/behavior_afs_luna_smoke.json
```

실제 출력되는 `AFS_CAMPAIGN`과 `REPORT`를 보관한다. 산출물은
`/workspace/g1_failure/runtime/afs_benchmark/<새 실행 시각>/` 아래에 저장된다.
중단 시 출력된 **새 Luna 캠페인의** 재개 명령을 사용한다. 재개에는 `--config`를 붙이지 않는다.
예전 Astra 캠페인을 Luna로 덮어쓰지 않는다. 기본 Astra 설정 파일도 보존한다.
새 실행의 protocol/model, command.json, API 응답의 반환 model, usage를 확인해야 한다.
키는 환경 변수로만 전달하고 설정/문서/로그에 복사하지 않는다.

현재 도구 환경에는 API 키가 없어 **실제 Luna API/GPU 결과는 아직 없다**.
합성 캠페인이나 request body 검사는 Luna의 시각 판단·보행 성공 증거가 아니다.
호출 수 상한은 금액 상한이 아니며, 실제 토큰·캐시·반환 모델과 제공자 요금을 확인해야 한다.

## 2. 개선 순서

1. **비용·실행 연결 확인:** 이번 Luna 소규모 실행으로 인증/이미지/schema/제안 연결과
   호출·토큰·지연을 확인한다. 로봇 모델은 AFS/Random 양쪽에서 동일해야 한다.
   중단된 INCONCLUSIVE 기록의 관측 토큰이 importer에서 누락되는 문제와,
   로봇 feedback 원문 누적에 따른 입력 증가가 후속 개선 대상이다.
   요약 입력을 도입할 경우 raw 근거는 유지하고 새 prompt/robot 조건으로 별도 검증한다.
2. **성공 대조와 관측 경계 확보:** 이전 유효 결과는 양쪽 모두 4/4 FAIL이었다.
   이것만으로 탐색 우월성을 보일 수 없다. 개발용 장면에서 우회가 쉬운 조건부터
   통로 폭·장애물 배치 등을 단계적으로 바꾸고 성공/실패 양쪽과 반복 변동을 확보한다.
   질량만 더 무겁게 만드는 방향으로 고정하지 않는다. 개발 결과로 정한 domain은
   정식 평가 전에 고정하고 개발 자료와 새 비교 예산/seed를 구분한다.
3. **기하 축과 시나리오 확장:** 기존 생성기를 goal-agent의 versioned scene contract에
   연결한다. SceneGraph/지도/XML/로봇 관측의 ID·좌표·revision과 실제 물리 반영을 검사한다.
   확장 domain에서도 AFS/Random에 같은 조건·전체 공간·유효 예산을 적용한다.
4. **근거 있는 다양성과 회귀:** 목표 진척, 정체·재계획·접촉·물체 변위, 반복 결과를
   이용해 사건 검출을 검증한다. 필요한 신호가 없는 미끄럼/회복 여유는 추정값을 실측처럼
   쓰지 않는다. 검증된 유형 규칙과 회귀 실행기는 별도 구현하고, 미지원 유형은 UNKNOWN/
   UNSUPPORTED로 남긴다. 장면 종류 수를 6종 failure taxonomy coverage로 세지 않는다.

접촉/넘어짐/기술 실패는 관측이며, 고정된 최초 목표·예산에서 최종 달성 여부를 판정한다.
AFS나 평가자가 이동 경로·밀기 방향·점프 시점을 지정하지 않는다. 로봇이 설치된 기능으로
방법을 선택한다. 정적 지도에 `no_path`가 있다는 것만으로 조작 가능한 장면을 불가능 판정하지 않는다.

## 3. 밀기 외에 무엇을 시험할 것인가

| 장면/과제 | 탐색할 환경 요소 | 현재 지원과 추가 작업 |
|---|---|---|
| 우회·미로·여러 방에서 목적지 도달 | 장애물 위치/크기, 갈림길, 문 위치, 우회 거리 | 생성기/내비게이션 경로는 존재. 현재 goal-agent AFS에는 기하 adapter 연결 필요 |
| 좁은 문·코너 통과 | 통로 폭, 회전 공간, 장애물 간격 | 기존 보행·계획기 재사용 후보. 폭/배치의 실제 실행 연결과 성공 대조 필요 |
| 미끄러운 바닥에서 이동·방향 전환 | 바닥 마찰, 저마찰 구간 위치, 코너와 조합 | 전역 바닥 마찰은 현재 지원. 구간별 마찰/기하 결합과 slip 계측은 추가 작업 |
| 경사·작은 단차·불규칙 지형 이동 | 경사각/폭, 단차 높이, 거칠기 | 독립 생성기/terrain runner 존재. goal-agent 연결과 제어 가능 범위 검증 필요 |
| 조명·가림 조건에서 의사결정 | 조명, 시야 가림, 유사 외형 | 관측 변형/판단 계측 필요. 현재 GT 지도도 제공하므로 순수 시각 인식 시험이라고 부를 수 없음 |
| 점프·틈 넘기 | 틈 폭, 턱 높이, 착지 공간/마찰 | **현재 jump executor 없음.** 실제 도약·비행·착지/회복 제어 모델과 adapter부터 필요 |
| 들어 옮기기·잡아당기기 | 물체 형상/질량, 배치, 접촉 조건 | 현재 grasp/carry/pull 실행기 없음. 별도 로봇 기능 개발 필요 |

현재 goal-agent 기능은 `plan_path`, `navigate_to`, 제한된 속도 명령 `move`, `observe`,
`stop`, 가까이 정렬된 상자를 짧게 앞으로 미는 `push_object`다.
`request_skill`에 jump를 요청할 수 있다는 것과 물리적으로 실행된다는 것은 다르다.
GPT 모델 변경만으로 CUDA 보행 모델이 점프 정책이 되지 않는다. 위치를 순간이동하거나
외력을 인위적으로 가해 점프 성공처럼 처리하지 않는다.

따라서 **우회/통로/마찰의 실제 연결을 먼저 진행하고**, 점프는 교체 가능한 로봇 capability
개발로 분리하는 순서를 권장한다. 점프가 완성될 때까지 AFS 연구를 중단할 필요는 없다.
후속 확대 실험은 충분한 예산으로 전체 탐색/반복 순서를 실행하고, 독립 campaign seed를
늘린 뒤 FDR/Gain/검증된 coverage와 전체 비용을 함께 보고한다.

이 문서의 장면 확장·계측·새 로봇 기술은 계획이며 이번 모델 설정 변경으로 구현된 것이 아니다.
