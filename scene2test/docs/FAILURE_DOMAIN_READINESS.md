# 실패 유형과 장면 도메인 지원 점검

현재 AFS의 장면 생성 범위와 실패 유형 측정 규칙을 오프라인으로 점검하는 도구다.
규칙 구현, 해당 조건을 만드는 환경 제어, 실제 실패 발견을 분리한다.
2026-10-02 코드 기준으로 세 operational 규칙만 있으며, 이 사실은 세 유형을 발견했다는
뜻이 아니다. 6종 중 4종 발견이라는 연구 목표에는 측정과 장면 범위 확장이 필요하다.

## 실행 방법

기존 프로젝트 환경에서 실행한다. API 키, GPU, MuJoCo 렌더링은 필요하지 않다.
로봇과 LLM을 실행하지 않으며 기존 캠페인이나 저장된 결과를 변경하지 않는다.

```bash
cd /workspace/g1_failure/src/physical_ai_test_gen/scene2test
uv run --no-sync python tools/audit_failure_domain.py
```

기본 대상은 현재 17축 `clear-path-obstacles-v3`다.
결과는 `/workspace/g1_failure/runtime/failure_domain_audit/<새 실행 시각>/`에 저장된다.
출력된 `REPORT`의 HTML을 열면 유형별 상태와 장면 제약을 볼 수 있다.
`audit.json`, `families.csv`, `manifest.json`도 생성하며 기존 폴더는 덮어쓰지 않는다.

이전 5축 도메인을 확인하거나 파일 없이 JSON만 출력할 수도 있다.

```bash
uv run --no-sync python tools/audit_failure_domain.py --schema clear-path-corridor-v2 --stdout-only
```

지원 도메인은 v1 상자와 옆 공간, v2 통로, v3 다중 장애물, v4 목표 주변 배치다.
별도의 미로·지형 생성기는 이 감사 대상이 아니다. `--output-dir`로 새 저장 폴더를
지정할 수 있으며 `--stdout-only`와 함께 사용할 수 없다.
검사가 완료되면 종료 코드는 0이다. 이는 연구 목표 달성이 아니라 점검 완료를 뜻한다.
실제 지원 부족은 `READINESS.status=INSUFFICIENT_RULE_SUPPORT`로 표시한다.

새 18축 v4는 목표 영역을 처음부터 점유하는 장면을 생성할 수 있다.
기본 v3 감사와 구분하여 다음 명령을 사용한다.

```bash
uv run --no-sync python tools/audit_failure_domain.py --schema clear-path-goal-region-v4
```

v4에서는 구체적인 빈 목표·부분·전체 점유 예제를 구성한 근거로
`CONSTRUCTIVE_INITIAL_OCCUPANCY`를 반환한다. 다만 규칙은 여전히 세 개이므로
4/6을 위한 `INSUFFICIENT_RULE_SUPPORT` 상태와 실제 Coverage=null은 유지된다.

## 현재 확인된 공백

| 실패 유형 | 규칙 구현 | 장면과 관측에서 남은 일 |
|---|---|---|
| 충돌 | 시간적 연관 규칙 있음 | 접촉 기하·힘·진행 기록은 있으나 접촉만으로 목표 실패나 원인을 확정하지 않음 |
| 장애물 간섭 | 시간적 연관 규칙 있음 | 장애물과 계획 결과를 관찰할 수 있으나 정적 no_path는 로봇 전체의 불가능성 증명이 아님 |
| 목표 위치 점유 | 시간적 연관 규칙 있음 | v1/v2/v3는 초기 점유 불가. v4는 초기 배치를 제어할 수 있지만 실제 실행 검증 필요 |
| 도달 불가 | 미지원 | 로봇의 가용 행동을 고려한 독립적인 판단 근거가 필요 |
| 작업자 안전 위험 | 분류기 미지원 | 실험용 측정 계약·계산기는 있음. 실제 사람 장면과 검증된 상태 기록 연결은 미완료 |
| 인식 오류 | 미지원 | 로봇의 인식 주장과 센서·정답 자료를 연결하는 근거가 필요. 현재 GT 지도 지원도 명시해야 함 |

모든 유형의 `observed_failure_count`와 전체 발견 Coverage는 `null`이다.
이 도구는 실험 archive를 분석하지 않기 때문이다. 미측정을 0건 발견으로 해석하면 안 된다.
실제 관측 지표는 [실패 발견 측정기](FAILURE_DISCOVERY_MEASURES.md)와
[유형 측정 및 회귀 도구](BEHAVIOR_TAXONOMY_AND_REGRESSION.md)를 사용한다.

### 기존 v3에서 초기 목표 점유가 불가능한 근거

고정 목표는 `(7, 0)`, 목표 영역 반지름은 `0.25m`다. 현재 v3에서 목표에 가장 가까운
정적 블록의 중심 X 상한은 `5.75m`, 두 수평 변의 길이 상한은 각각 `0.8m`다.
회전을 모두 고려해도 블록의 오른쪽 끝은 다음 상한을 넘지 않는다.

```text
5.75 + sqrt(0.8² + 0.8²) / 2 = 약 6.316m
목표 원의 왼쪽 끝 = 7.0 - 0.25 = 6.75m
```

감사 코드는 상자와 벽도 포함한 모든 초기 물체의 보수적 XY 경계와 목표 원의
분리 거리 하한을 계산한다. 모든 하한이 양수일 때만
`PROVEN_DISJOINT_AT_INITIALIZATION`을 반환한다. 보수적 경계가 겹치는 경우에는
실제 점유 가능성을 증명한 것이 아니므로 `UNKNOWN`으로 남긴다.
이 계산은 명시적으로 지원하는 장면 생성식에 한정되며 관련 소스 해시를 저장한다.
v4에서는 상자의 X 범위가 달라지므로 위 v3 분리 결론을 적용하지 않고 구체적인 점유 예제를 검증한다.

로봇이 나중에 상자를 목표 쪽으로 밀 수 있으므로 **실행 중 목표 점유가 불가능하다는
주장은 아니다**. 기존 `goal_occupied` 규칙은 실행 후 상태를 관찰하는 데 여전히 의미가 있다.
또한 정적 블록으로 목표를 완전히 막아 놓기만 하면 손쉬운 실패를 반복할 위험이 있다.
확장 시에는 빈 목표·부분 점유·이동 가능한 점유와 성공 측면 대조를 함께 설계해야 한다.

### 정적 지도 검사의 한계

보고서에는 기본 장면 또는 폭 상·하한 장면의 SceneGraph·지도 해시와 정적 경로 유무를
넣는다. 이는 장면 생성과 지도 연결 점검이지 로봇 rollout이나 전체 탐색 공간의 경로 보장은 아니다.
이 지도는 fixture의 발자국 설정을 쓰며, live 추종기의 추가 여유·복구 동작과 동일하지 않다.
정적 경로가 없어도 물체 이동 등 로봇의 행동 가능성이 남아 있으므로 goal FAIL을 부여하지 않는다.

## 연결된 확장과 남은 작업

[18축 목표 주변 물체 배치와 AFS](GOAL_REGION_AFS.md)를 구현했다. 생성기·SceneGraph·
지도·물리가 같은 배치를 사용하며, 기존 동적 상자로 빈 목표·부분·전체 점유를 구성한다.
로봇의 목표·능력·행동 선택은 유지한다. CPU/합성 검증과 실제 로봇 성공을 구분해야 한다.

[네 번째 유형의 근접 측정 설계](HUMAN_PROXIMITY_CONTRACT.md)는 계약과 참조 계산기까지
구현했다. 사람 장면·검증된 archive 연결·실제 규칙 등록은 아직 남아 있다. 안전 사건을
목표 실패로 바꾸거나 no_path를 도달 불가로 이름만 바꾸는 방식은 사용하지 않는다.
추가 규칙 하나는 최소 필요 조건일 뿐, 네 유형의 실제 발견을 보장하지 않는다.
장면 범위 확장과 별개로 기존 AFS의 행동 근거·완화 탐색·중복 억제·반복 선택 품질도 검증한다.

3.2m 폭 실험의 재시도는 필요 조건이 아니며 기존 suite는 그대로 보존한다.
새 장면 도메인이나 로봇 조건을 기존 동결 캠페인에 섞지 않는다.
전체 단계는 [프로젝트 로드맵](PROJECT_ROADMAP.md)을 따른다.

[v4·측정 계약 확장 이력](../../.workhistory/2026-10-02_goal_region_afs_and_human_contract.md)에
각 구현과 검증을 구분해 기록했다.
