# 로봇 경로 추종과 수치 명령 피드백

2026-10-02. 목표 체류 옵션을 켠 사용자 실행에서, 경로가 있는데도 출발점 부근에서 회전하고
이후 설명과 달리 0속도 명령을 반복한 문제를 점검했다. 이 문서는 로봇 내부 수정과 진단,
AFS로 전달하는 근거, 다음 단독 실행 방법을 설명한다. 후속 사용자 실행에서는 실제 전진이
늘었지만 상자 주변의 발자국 여유를 침범한 뒤 정체했다. 현재 버전은 이 문제를 수정한
`clearance-recovery-v3`다. 이 버전에서 검토한 동일 조건 사용자 실행 2회가 모두 Luna/CUDA로 원래 목표에 도달했다.
복구 기능은 필요하지 않아 호출되지 않았으므로, 복구 자체의 실제 보행 성능은 아직 미검증이다.

## 새 버전의 실제 성공 결과

5회의 navigate_to만으로 10회 예산 안에서 VALID/PASS를 확인했다. 전체 시뮬레이션 66.815초,
최종 거리 0.11807m, 목표 반경 0.25m 내 연속 체류 약 1초다. 연결 차단·복구·밀기·넘어짐·
비바닥 로봇 접촉은 없었다. 이번 성공은 새 경로의 통과 근거이며 복구나 밀기 성공 근거는 아니다.
최종 자세 유지는 0.015초만 실행됐고 대부분의 체류는 목표 영역 안에서 접근하며 누적됐다.
실제 장시간 자세 유지와 반복 성공률은 별도 검증 대상이다.

49개 산출물 해시와 기존 목표 판독기로 결과를 확인했다. 상세 내용은
[실제 성공 검토 이력](../../.workhistory/2026-10-02_navigation_v3_live_pass.md)에 있다.
과거 FAIL과 장면·목표·예산은 같지만 로봇 코드가 다르므로 동일 조건 실패 경계로 합치지 않는다.

동일 protocol·scene.xml로 재실행한 결과도 VALID/PASS였다. 이번에는 첫 요청이 0.2초여서
총 6개 호출을 사용했고, 시뮬레이션 77.660초·최종 거리 0.11391m·목표 체류 약 1초를 기록했다.
차단·복구·밀기·비바닥 접촉·넘어짐은 없었다. 두 기록은 기존 failure memory에서
PASS 2/FAIL 0의 success_control 한 개로 묶이며, 이는 일반 성공률 100%라는 뜻이 아니다.
이제 로봇 조건을 고정하고 AFS 단일 축 대조 탐색을 이어갈 수 있다. 상세한 비교와 한계는
[재실행 검토 이력](../../.workhistory/2026-10-02_navigation_v3_repeat_pass.md)에 기록했다.

## 확인한 현상과 해석 범위

이전 실행은 API 10회가 완료된 유효한 목표 FAIL이다. 최종 거리는 약 6.27m였고,
목표 영역에 들어가지 않아 `goal_dwell_v1`의 자세 유지 기능은 실행되지 않았다.
세 번의 이동은 모두 경로를 찾았으나 회전 위주로 정체했다. 뒤의 다섯 `move`는 설명에
횡이동을 언급하면서 실제 `vx_mps`, `vy_mps`, `yaw_rate_rps`를 모두 0으로 보냈다.
수치 파서는 0이 아닌 횡이동을 허용하고 그대로 보존한다. 프롬프트만으로 해결된다고
주장하지 않으며 모델이 0을 반복 선택한 내부 원인은 확인되지 않았다.

기존 추종기의 가까운 경로점 추종은 별도 운동학 테스트에서 정체가 재현됐다.
이는 코드 수준의 결함 재현이며, 이전 G1 실패의 유일한 물리적 원인을 입증한 것은 아니다.

후속 `clearance-lookahead-v2` 실행은 최종 목표 거리가 2.18m까지 줄었으나 여전히 FAIL이었다.
계획 경로점의 추가 여유가 최소 약 1.42cm였고, 보행 중 상자 AABB까지의 거리가 반경
0.40m 아래로 내려갔다. 기존 연결 검사는 선분의 시작점까지 검사하므로 바깥으로 나가는
방향도 모두 차단했다. 한 행동은 10초 중 8.25초 동안 0 명령을 냈다. 실제 비바닥 접촉이나
넘어짐은 기록되지 않았다. 보수적인 경로 여유 침범과 물리적 충돌을 혼동하면 안 된다.

## 로봇 내부 경로 추종 변경

`clearance-recovery-v3`를 goal runner의 `navigate_to`에 연결했다.

- 기존 BFS가 계산한 경로에서 가까운 진행 지점을 찾고, 경로 길이 기준 최대 0.35m 앞의
  점을 선택한다. 전체 경로에서 가장 가까운 점을 찾지 않아 멀리 돌아오는 가지로 건너뛰지 않는다.
- 전진만 하며 가까운 점을 선회하는 대신, 거리 비례 속도와 제한된 횡이동을 사용한다.
  속도 벡터 크기 최대 0.20m/s, 횡속도 최대 0.15m/s, 회전 최대 0.40rad/s다.
  목표가 뒤에 있으면 먼저 회전한다. 속도 제한 시 두 축을 함께 줄여 방향을 보존한다.
- 기본 원형 발자국 반경 0.40m를 줄이지 않고 계획에 0.10m 보행 오차 여유를 더한다.
  BFS 격자는 셀 사이 연결도 여유를 지키도록 반 셀 대각선 약 0.035m를 추가 보수적으로 반영한다.
  정확한 시작점·GPT 목표가 추가 여유 안쪽에 있으면 최대 0.35m 연결만 원래 발자국으로 검사한다.
  연결 불가 시 `no_tracking_clearance`를 돌려주며 좁은 전체 경로에 작은 반경을 몰래 적용하지 않는다.
- 현재 위치와 선택점 사이의 선분을 연속 검사한다.
  얇은 장애물을 듬성듬성 샘플링해서 놓치지 않도록 선분과 AABB의 최소 거리를 검사한다.
  모서리를 가로질러 추가 여유를 소모하지 않도록 각 장애물의 시작·끝점 거리까지 고려한다.
- 연결이 막히면 로봇 내부에서 현재 기하를 다시 읽고 아래의 제한된 복구 또는 재계획을 한다.
  진행할 수 없으면 남은 행동 시간 동안 0 명령을 반복하지 않고 구체적인 이유를 GPT에 반환한다.
  자동 순간이동·GPT 목표 변경·추가 LLM 호출은 없다. 도구 오류 자체가 목표 FAIL은 아니다.
- 정상 추종은 행동/재계획 시 GT 기하 스냅샷을 쓰고, 차단 및 복구 중에는 다시 읽는다.
  전신 충돌 안전, 실제 보행 오차의 상한, 일반적인 동적 장애물 회피를 보장하지 않는다.

## 제한된 여유 복구

복구는 이미 침범한 보수적 발자국 여유에서 빠져나오는 로봇 내부 기능이다. 물체를 통과하거나
치우는 새 기술이 아니다. 침범 깊이가 0.06m를 넘거나 base가 실제 AABB 내부에 있으면 자동 복구하지 않는다.

- 현재 위치에서 최대 0.35m 안의 바깥 지점을 탐색한다. 가까운 장애물에 대한 거리의 초기 방향 미분이
  음수가 아니고, 다른 장애물에는 새 발자국 침범을 만들지 않는 연속 선분만 허용한다.
  끝점은 최소 0.515m 여유를 갖는다. 바닥 경계도 함께 검사한다.
- 복구 명령은 최대 0.10m/s, 회전 0이며 현재 몸체 좌표계로 변환한다. 뒤로 또는 옆으로 빠질 수도 있다.
  실제 움직임을 확인하며, 시작 대비 여유가 2cm 넘게 악화되거나 연결이 더 이상 유효하지 않으면 종료한다.
- 1초 동안 복구 지점까지의 거리가 5mm 이상 줄지 않으면 `recovery_no_progress`,
  3초를 소모하면 `recovery_timeout`으로 도구를 반환한다. 복구 반경을 벗어나도 종료한다.
- 여유를 회복하면 같은 GPT 목표로 다시 계획한다. 행동당 재계획은 최대 2회이며
  복구는 이보다 많은 횟수로 반복하지 않는다. 재계획 실패도 구체적인 상태로 반환한다.
- 모든 복구와 재계획은 **기존 행동 마감 시각 및 시뮬레이션 예산 안에서** 수행한다.
  짧게 요청한 행동에는 복구 시간을 추가하지 않는다. `plan_path`는 조회만 하며 로봇을 복구 이동시키지 않는다.

추가 여유 때문에 이전보다 보수적으로 경로를 거절할 수 있다. 이는 이 로봇 계획기의 제약이지,
장면이 모든 로봇 또는 밀기 등을 포함한 모든 방법에 대해 불가능하다는 증거가 아니다.

AFS나 평가기가 경유점·미는 방향을 지시하지 않는다. GPT가 선택한 대상과 시간 안에서
로봇 내부 추종기가 움직인다. 목표 평가와 체류 처리 옵션은 별도 모듈로 유지한다.

## 수치 명령과 측정 결과

`action-motion-v1`은 추론 대기 이후 실제 행동 시작부터 종료까지를 측정한다.

- 행동 시작·종료 시각과 위치, 세계 좌표 및 시작 시 로봇 좌표 기준 변위.
- 순이동 거리, 목표 거리 감소량, 순 회전각, 평균 명령, 회전 제한에 걸린 샘플 비율.
- 실제 `move` 수치와 `commanded_stationary`, 이동 연결 차단 샘플 수.
- 적분된 base 이동 길이는 보행 흔들림을 포함하므로 유효한 전진 거리와 구분한다.

다음 GPT 입력의 `execution_feedback`에 직전 측정과 최근 8개 기억 내 연속 0속도
명령 횟수, 현재 로봇의 전방·왼쪽 축을 세계 좌표로 표시한다. 지침과 수치 필드 설명은
`plan_summary`가 실행 코드가 아니며 실제 움직임은 수치 필드가 결정한다는 점을 명시한다.
0 명령은 여전히 유효하다. 물리적으로 흔들리거나 밀릴 수 있으므로 0 명령과 실제 정지는
구분한다. 설명을 해석해 임의로 비영속도를 넣거나 응답을 재시도하지 않는다.

첫 구현에서 이 측정은 일반 도구 실행에 연결했다. 별도 push 실행기는 기존 skill 피드백을
사용하며 새 motion 측정이 없는 경우 null로 남긴다. 이전 기록의 누락도 0으로 만들지 않는다.

## 산출물과 AFS 연결

| 파일 | 확인할 항목 |
|---|---|
| `protocol.json` | `navigation_follower`, `execution_feedback_version`, 새 모듈 해시 |
| `states.jsonl` | `navigation_tracking`: 경로 인덱스, 선택점, 명령 직전 위치·방향, 회전 오차, 명령 |
| `decisions.jsonl` | `tool_result.result.motion`, 마지막 `navigation_tracking`, 기존 목표 진행 상태 |
| `goal_context_NNN.json` | 해당 호출에 전달한 `execution_feedback` |
| `navigation_context_NNN.json` | 추론 대기 후 계획/추종 시작 시 실제 위치와 기하 스냅샷 |
| `navigation_trace_NNN.json` | 차단·복구·재계획 시각, 기하, 새 경로, GPT 목표 및 원래 행동 마감 시각 |
| `rollout.mp4` | 기존 MP4 기록 유지, GIF 없음 |

상태 로그는 기존 20Hz 간격이다. 명령 직전 진단과 적분 후 상태를 같은 행에 기록하며,
모든 200Hz 명령의 완전한 재생 로그라는 뜻은 아니다. 동작별 motion 집계는 각 적분 단계에서 한다.

P1 행동 분석과 AFS `action_timeline`에도 행동 시작 시각, 행동만의 소요시간, 순변위,
목표 거리 감소, 0명령 여부, 회전 제한 비율, 연결 차단 횟수를 선택적으로 보존한다.
v3의 복구·재계획 횟수, 상태, 이벤트 시간선도 검증해 전달한다. 정상·복구 명령은 상태 로그로
구분하고, 0 명령 없이 즉시 반환한 차단은 motion 샘플 수가 아니라 복구 이벤트에서 확인한다.
전체 재계획 경로는 trace에 저장하며 GPT 기억/AFS 요약에는 짧은 결과를 전달한다.
측정값이 잘못됐으면 해당 분석을 INVALID/PARTIAL로 표시하며 로봇 결과를 변경하지 않는다.
새 실패 유형 detector나 인과 추론은 추가하지 않았다.

## 다음 단독 실행

아래는 유료 로봇 API 최대 10회, AFS 호출 0회인 새 실행이다. 기존 키·CUDA·MuJoCo·GR00T
환경을 사용한다. 기존 실행이나 동결 캠페인을 재개하는 명령이 아니다.

```bash
cd /workspace/g1_failure/src/physical_ai_test_gen/scene2test
```

```bash
uv run --no-sync python tools/run_robot_goal_agent.py --live --model gpt-6-luna --max-calls 10 --enable-push --response-timeout 300 --evaluation-profile goal_outcome_v1 --navigation-completion goal_dwell_v1 --scene-config /workspace/g1_failure/runtime/afs_benchmark/20260929T163123_122521Z/attempts/attempt_00006/scene_config.json
```

시작 로그에서 다음 버전을 확인한다.

```text
NAVIGATION_FOLLOWER=clearance-recovery-v3; EXECUTION_FEEDBACK=action-motion-v1
```

새 결과는 `/workspace/g1_failure/runtime/robot_goal_agent` 아래 새 시각 폴더에 저장된다.
원본 결과와 기존 AFS 캠페인을 덮어쓰지 않는다. 목표·10회 예산·클라이언트 기본 출력 토큰 상한 없음·
추론 시간의 시뮬레이션 포함·timeout·재시도 없음은 유지한다. `--max-seconds`를 생략했으므로
시뮬레이션에 암묵적인 120초 상한은 없다. 제공자/모델의 출력 한도는 여전히 적용된다.

수정 전과 로봇 코드·프롬프트가 다른 새 조건이다. 과거 표본과 단일 조건 bracket을 만들거나
완료된 AFS/Random 비교에 추가하지 않는다. 기존 동결 회귀 suite도 새 코드로 재개하지 않는다.

## 검증과 후속 판단
