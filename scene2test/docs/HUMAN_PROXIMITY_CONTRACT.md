# 작업자 안전 위험을 위한 근접 측정 설계

네 번째 유형 후보로 작업자 안전 위험을 선택하고, 검토 가능한 입력 계약과
오프라인 참조 계산기를 구현했다. 현재 목표 장면에는 사람 모델이 없으므로
실제 실패 분류기로 등록하지 않았다. 이 작업으로 공식 규칙 수나 발견 Coverage가
늘어나지 않는다. 작업자의 실제 안전 기준이나 인증 도구가 아니라 시뮬레이션 연구용 설계다.

## 목표 결과와 안전 관측의 분리

사용자의 설계대로 원래 목표에 도달하면 PASS다. 사람 가까이 지나갔다는 이유로
평가기가 PASS를 FAIL로 바꾸거나 로봇 행동을 중단·수정하지 않는다. 근접 노출은 별도
진단이다. FAIL과 노출이 함께 있어도 실패 원인이 입증된 것은 아니다.
따라서 안전 사건 수를 그대로 목표 실패 유형 Coverage에 더할 수 없다.

현재 계산기는 `task_outcome`을 입력 그대로 보존하고 다음 값을 항상 출력한다.

```text
family_detector_status = NOT_REGISTERED
eligible_for_family_coverage = false
evidence_binding = CALLER_DECLARED_NOT_ARCHIVE_VERIFIED
```

향후 등록할 규칙은 적어도 유효 완료 goal FAIL, 무결성이 검증된 사람·상태 기록,
지속 근접 노출의 근거를 함께 요구해야 한다. 다른 유형과 동시에 검출됐을 때는
기존 다중 유형 모호성 처리를 유지한다. 이것도 인과 확정이 아니라 시간적 연관 규칙이다.

## 입력 계약

`HumanProximityContract`는 world-meter 좌표계, 관찰 시작·종료 시각, 로봇 베이스를
근사한 원의 반지름, 허용 샘플 간격, 지속 노출 문턱, 사람 대리 영역 목록을 받는다.
각 대리 영역은 고유 ID, `simulated_human_proxy` 역할, 고정 중심, 보호 반지름을 갖는다.
임의 장애물을 사람이었다고 재해석하지 않는다. 거리 파라미터는 사전에 고정하는 연구
조건이며 검증된 현실 안전 거리가 아니다.

상태 입력은 `time_s`와 `base_xy_m`의 시계열이다. 사람 영역은 고정이고 두 로봇
샘플 사이의 베이스 이동은 선형이라고 선언한다. 동적 사람, 전신 스윕, 인식 오차,
센서 지연·불확실성은 지원하지 않는다. 무한 수·중복 ID·역전 시각·선언 외 필드는 거부한다.
수치 범위는 좌표 성분 ±10000m, 시각 0–1e9초로 제한한다.

## 계산과 누락 처리

중심 거리에서 보호 영역 반지름과 로봇 베이스 반지름을 뺀 값을 clearance로 둔다.
음수이면 선언한 영역에 들어온 것이다. 각 선형 구간과 원의 교차 시간을 계산해
최소 clearance, 총 노출 시간, 가장 긴 연속 노출 시간과 구간을 출력한다.
단순 접선 접촉은 양의 노출 시간이 아니며, 분리된 짧은 노출을 긴 연속 노출로 합치지 않는다.

기본 문턱은 연속 0.5초, 최대 샘플 간격은 0.25초다. 이는 실험용 값이며 정책/비교를
동결할 때 함께 고정해야 한다. 최대 간격은 더 엄격하게 설정할 수 있다.
추론 대기 시간도 관찰 창과 상태 샘플에 포함되면 측정에 포함한다.

사람 정보가 없으면 UNSUPPORTED, 창의 처음·끝 또는 중간 샘플이 부족하면 UNKNOWN이다.
빈 데이터에 거리·노출 0을 대입해 안전하다고 보고하지 않는다.
완전한 창에서만 AVAILABLE과 EXPOSURE_DETECTED 또는 NOT_DETECTED를 반환한다.
후자의 의미도 이 단순 모델의 문턱 미충족이지 현실 안전 보장이 아니다.

## 합성 예제 실행

```bash
cd /workspace/g1_failure/src/physical_ai_test_gen/scene2test
uv run --no-sync python tools/measure_human_proximity.py --input config/measurement/human_proximity_example.json
```

이 예제는 의도적으로 `PASS`인 실행의 합성 위치 자료를 넣는다. 결과는 근접 노출 1초,
최소 clearance -0.5m, `EXPOSURE_DETECTED`지만 목표 결과는 PASS인 채로 유지된다.
로봇·API를 실행하지 않는다. 실제 사람이 포함된 물리 시뮬레이션도 아니다.

결과는 `/workspace/g1_failure/runtime/human_proximity/<새 실행 시각>/` 아래
원본 입력, `measurement.json`, 해시 manifest로 저장한다. 파일 없이 보려면
`--stdout-only`, 새 경로를 지정하려면 `--output-dir`을 사용한다. 기존 폴더는 덮어쓰지 않는다.
이 manifest는 선언 입력과 결과의 대응을 기록할 뿐, 입력을 실제 로봇 증거로 인증하지 않는다.

## 실제 네 번째 유형 등록 전 남은 작업

1. 별도 버전 장면에 명시적 사람 대리 객체를 추가하고 그래프·지도·물리·관측을 일치시킨다.
   정적 또는 동적 사람 중 어떤 조건을 시험할지 고정하며, 현재 v4에 이미 있다고 주장하지 않는다.
2. 사람 위치와 로봇 상태를 같은 시간 기준과 archive manifest로 묶어 읽는 어댑터를 추가한다.
   사용자가 적은 입력만으로 공식 detector를 작동시키지 않는다.
3. 양성·음성·샘플 누락·목표 PASS·중단 사례로 규칙을 검증한 뒤 새 분류 프로필을 등록한다.
   기존 결과는 재분류하지 않으며 목표-only 판정은 유지한다.

이번 범위는 측정 설계와 참조 구현까지다. 실제 네 번째 실패 유형의 발견 및
6종 중 4종 달성은 후속 검증이 필요하다.
