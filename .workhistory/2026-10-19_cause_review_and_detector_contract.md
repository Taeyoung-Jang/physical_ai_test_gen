# LLM의 지난 결과 분석과 실패 검출 조건 연결

## 배경과 목표

사용자 실행 `runtime/afs_autonomous/20261019T031027_016099Z`는 4회 시도 중 유효 FAIL 3개와 API 시간 초과 제외 1개에서 중단됐다. 관측 FDR은 3/3이지만 측정 유형은 0종이었다. 새 행동 피드백은 실제 요청에 전달됐으나 목표 접근·경로 계획 실패가 반복됐다. 상자 마찰 후보는 PASS 기준의 무릎–상자 접촉을 근거로 충돌을 예측했지만 기존 충돌 규칙은 clear_box_geom 접촉을 제외한다. 접촉 반응이 달라질 가능성과 측정 충돌을 구분해야 한다.

사용자는 검출 조건을 제안에 연결하고 AFS 내부 LLM에게 실패 이유를 분석시키는 개선을 승인했다. 기존 LLM도 vulnerability, hypothesis, alternative, falsification을 작성했지만 별도의 지난 결과 분석을 제출하지는 않았다.

## 구현

새 `feedback_policy: cause-review-v2`는 breadth-v1, expanded-ten-v1, failure-branch-v3 계약에서만 활성화한다. 새 설정은 `scene2test/config/afs_cause_review_luna.json`이다. Luna·유효 12개 목표·최대 16회 시도·AFS 20요청·축당 4회·반복 0회·history_limit 4·300초 응답 대기는 그대로다. 로봇, 목표, 물리, 분류 기준과 성과 집계는 변경하지 않았다.

한 AFS 호출에서 `episode_reviews`를 먼저 받고 `spaces`를 그 뒤에 받는다. 최신 제시 에피소드와 제시된 유효 FAIL이 필수 분석 대상이다. 분석은 관측 사실·행동 번호, 유력 가설, 다른 설명, 불확실성, 다음 실험 함의를 구분한다. PASS만 있으면 성공 전략을 검토한다. 시간 초과·제외를 유효 실패로 바꾸지 않는다. 별도 분석 API 호출은 없지만 추가 텍스트에 따른 토큰 비용은 늘 수 있다.

각 후보는 분석 대상 evidence ID를 참조하고 검출 근거·제외 조건·예상 접촉 대상을 `measurement_plan`에 설명한다. 호스트는 제시된 근거 ID, 실제 PASS/FAIL, 관측 행동 번호, 후보와 분석의 참조 연결을 검사한다. 스키마·근거·결과 오류는 전체 중단한다. 자유 텍스트의 사실성이나 원인을 자동으로 검증하지는 않는다.

`cause_review.py`는 기존 8개 지원 규칙의 요구 조건·제외 조건·버전과 기존 THRESHOLDS를 연결한다. 각 제시 기록에는 실제 종료 정체, 최근 경로 거절 수, 조건 충족 접촉 수, 검증된 형상과 사람 노출 계약도 전달한다. 누락 값은 None이며 미검출과 구분한다. unreachable과 perception_error는 계속 미지원이다.

상자 접촉만 예상하거나 접촉과 무관하다고 명시하면서 collision을 겨냥한 후보는 개별 제외한다. 유효 대안은 유지하고 모두 제외되면 기존 bounded rejection과 고정 요청 예산을 사용한다. 로봇 시도 또는 FAIL로 세지 않으며 Random 대체·보정·임계값 완화는 없다. unknown 접촉 범위는 불확실성으로 허용하므로 이 검사는 자연어 의미 판정이나 실패 확률 점수가 아니다.

선택 감사에 `llm_episode_reviews`와 비인과적 해석 한계를 저장하고 기존 원본 응답·보고서 흐름으로 보존한다. LLM 분석은 실제 대표 유형이나 목표 결과를 덮어쓰지 않는다. 기존 action-diagnostics-v1과 legacy 계약은 유지한다.

## 검증과 실행 범위

관련 CPU 합성 회귀 146개가 통과했다. 새 구조화 스키마, 근거·결과·행동 번호 오류, 후보 연결, 상자 전용 충돌 후보와 유효 대안 혼재, 모든 후보 거절의 요청 예산 소비, 저장 응답 중단 재개와 무재전송, 기존 모드를 포함한다. mock proposer/runner를 사용했으며 실제 모델 분석 성능 검증은 아니다.

최신 유효 실패 3개와 기존 PASS 하나로 읽기 전용 development_plan이 통과했다. 로봇 조건은 e8ec811981448476f029536ee0b49be2fcad786c53d86edc3a5ba5105813bd5b로 유지된다. 실제 최신 저장 메모리에서 분석 요청을 메모리 내 구성해 250KB 입력 제한 안에 들어가고 사람이 노출되는 계약과 최신 FAIL 분석 대상이 포함됨을 확인했다. API 키를 제거했고 요청을 전송하거나 DB·새 세션을 만들지 않았다.

Ruff와 형식 검사, git diff --check를 수행했다. 기존 API timeout을 고쳤다는 주장은 없으며, 새 방식의 실패 유형 발견 성과·비용 개선·4종 달성은 미검증이다. 새 유료 실행, GPU·로봇 실행, 기존 아카이브·DB·결과·예산 변경, 커밋·push는 하지 않았다.

기존 031027 세션과 완료된 numeric_recovery는 보존한다. 새 모드로 동결 소스를 우회 재개하지 않으며 별도 세션이 필요하다. 무료 plan과 유료 실행 명령은 AFS_BREADTH_SEARCH.md와 루트 README에 연결했다.

## 문서 기준

OpenAI Docs 지침으로 [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)를 확인했다. 모든 객체의 추가 필드를 금지하고 필드를 필수화했으며 출력 속성 순서를 분석 다음 후보로 정했다. 모델 교체·별도 추론 호출·출력 토큰 상한은 추가하지 않았다. 문서 작성 지침은 기능 검증과 미검증 성능을 구분해 기존 작업 기록에 보존하는 데 적용했다.
