# 발견 중심 AFS 선택과 유효 표본 예산 구현

## 목표와 변경

사용자 승인에 따라 실패율 30%와 근거 기반 실패 유형 4종의 동시 관찰을 우선하는
개발 탐색 모드를 구현했다. 기존 자동 순환·행동 피드백은 재사용하고, 발견 모드에서는
자동 경계 중간값과 반복 슬롯을 제거했다. 매회 LLM 요청, 가장 적게 사용한 적격 축,
직전 축 cooldown, 축별 쿼터, 전체 범위의 10% 이상 변화와 후보 거절 감사를 적용한다.
유효 후보가 없으면 멈추며 Random으로 대체하거나 유료 요청을 재시도하지 않는다.

SearchBudget에 명시적 selection_policy와 valid_rollout_target을 추가했다. 유효 목표와
총 시도 상한은 다르다. 제외는 총 시도만 소비하고 기존처럼 검토를 위해 중단한다.
수동 계속 지시도 예산을 늘리지 않는다. 상한 도달 시 목표 미달을 TARGET_NOT_REACHED로
표시한다. 기본 alternating-v1의 기존 16회 제한은 유지하고 새 모드만 큰 상한을 허용한다.

소규모 6유효/8시도 설정과 본 실험 20유효/24시도 설정을 추가했다. Luna와 회당 10호출
기준 로봇 상한은 각각 80/240, AFS는 8/24호출이다. 자동 세션은 여전히 외부 이력 기반
개발 탐색으로 Random/Gain 검증은 아니다. 다중 시드 독립 평가 실행은 추가하지 않았다.

새 실행만 사용하는 공동 발견 지표를 요약/HTML 보고서에 포함했다. 입력 이력의
분류는 별도 v2 측정으로 연결하되 새 성능 분모와 비용에서 분리한다. goal 판정·로봇
소스·기술·호출/시뮬레이션 제한·사람 노출 측정 기준을 변경하지 않았다.

## 검증과 제한

자동 순환, 유효 목표 종료, 제외의 상한 소비, 재개 무중복, 작은 제안 거절 및 큰
예산의 명시적 opt-in을 합성 실행기로 검사했다. 실제 human_clear 아카이브
20261018T004636_410637Z로 오프라인 plan 검증도 통과했다. 최초 통합 테스트 명령은 존재하지 않는
test_behavior_feedback.py 경로로 수집 실패하여 실제 파일명으로 다시 실행했다.

기존 32개 자동 탐색 테스트 통과에는 새 테스트 4개가 포함된다. 실제 API/로봇 실험은
수행하지 않았고 새 런타임 세션/DB를 만들지 않았다. 과거 결과·예산은 변경하지 않았다.
축 다양성은 유형 다양성이 아니며, 사람 규칙은 종료 직전 5초 측정에 한정된다. 따라서
이번 코드 구현 자체가 네 유형 발견 또는 30% 달성을 의미하지 않는다.

최종 통합 회귀는 test_afs_autonomous, test_human_archive_taxonomy,
test_discovery_measures, test_behavior_memory에서 **143 passed in 31.01s**였다.
Ruff check, format --check(5 Python files), git diff --check도 통과했다.
실제 아카이브의 최종 plan 재검증은 v5/20축/Luna/10호출/goal_dwell_v1/밀기 활성화를
그대로 유지하며 로봇 최대80호출·AFS 최대8요청을 출력했다. API·로봇·디렉터리 생성은 없다.
