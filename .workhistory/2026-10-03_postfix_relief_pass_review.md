사용자 실행 `20261003T154614_537450Z`는 **VALID/PASS/GOAL_REACHED**다. 원본 56개
artifact 해시가 일치하고, 직전 새 코드의 0.5 FAIL과 같은 로봇 조건에서 상자의 측면 배치만

이번 작업은 원본 검증, 행동·조건·비용 비교 및 문서 기록이다. 실행 코드, 원본 PASS/FAIL,

## 시간과 비용

6회 모두 HTTP 200, 자동 retry 없음, usage 6/6 관측, 충돌·누락 0이다.
새 실행 사용량은 입력 **151,198토큰**, 출력 **97,029토큰**이다. 금액이 아닌 제공자 보고
토큰 수이며, 호출 수가 줄었다고 비용도 줄었다고 결론내리지 않는다.

처음 두 요청이 전체 출력의 약 **98.3%**를 차지한다. 두 응답 모두 성공했고 요청한 행동은
각 0.2초였다. 이는 비싼 응답에 비해 실행 구간이 짧았다는 관측이지, 로컬 로그만으로
내부 reasoning이나 모델/서비스의 원인을 확인한 것은 아니다. usage에는 해당 내부 세부
분해가 없어 이를 추정 사실로 기록하지 않는다. 사용자가 제거를 요청했던 출력 상한을
임의로 복원하지 않았고 모델·effort·timeout도 변경하지 않았다.

전체 시뮬레이션 488.510초 중 도구 실행 구간 합은 약 36.970초다. 나머지는 settle과
추론 대기 구간이다. API 지연 합 490.239초는 wall clock으로 시뮬레이션 시간과 다른
시계다. 이번이 이전 FAIL보다 총 시간이 길어도 그것이 더 오래 걷거나 이동 능력이
낮아졌다는 뜻은 아니다. 시뮬레이션 120초 상한이나 API timeout으로 중단된 것도 아니다.

새 조건의 두 실행을 합하면 로봇 호출 16회, 관측 입력 473,907토큰/출력 142,066토큰이다.
이는 이번 PASS 한 회의 비용과 구분한다. 두 재실행에서 새 AFS 요청은 없었다. 옛 suite의
AFS 선택 비용·기존 로봇 비용은 이 합계에 섞지 않는다.

## AFS 연결과 후속 제안

두 검증된 새 조건 archive만으로 build_failure_memory를 읽기 전용 실행했다.
두 장면·두 episode, 제외 0·중복 0·관측 bracket 1개다. 0.5는 FAIL 1/PASS 0,
0.75는 PASS 1/FAIL 0이다. states/events/actions/object_motion은 모두 AVAILABLE이고,
compact AFS 근거에 각각 10개와 6개의 행동 요약이 들어간다. 새로운 공식 failure family나
coverage를 부여하지 않았다. 이는 개발용 비교이며 AFS/Random Gain 근거가 아니다.

next_selection은 추가 LLM 호출 없이 기존 규칙으로 다음을 반환했다.

- strategy: observed_boundary_midpoint.
- 변경 축: box_lateral_fraction.
- 관측 구간: 0.5 FAIL – 0.75 PASS.
- 다음 후보: **0.625**.
- 현재 구현의 selected_plan 규칙은 하단 0.5를 기준으로 반복하고 중간값을 비교한다.

후속 권고는 새 예산의 **0.5 재확인 한 회와 0.625 중간값 한 회**다. 같은 장면에서도 결과가
바뀔 수 있으므로 기준 재확인과 새 환경 탐색을 함께 보는 것이 목적이다. 이 두 회를 실행한다면
최대 로봇 API 20회이며 별도 AFS 요청은 필요 없다. 이번 검토에서는 계획 파일·scene 파일·
suite를 만들거나 실행하지 않았다. 0.625는 아직 검증된 성공/실패 장면이 아니다.

이미 완료된 옛 suite나 중단한 폭 실험을 재개하지 않고, 새 조건 archive를 입력으로 하는
별도 개발 비교로 진행해야 한다. 코드나 예산을 바꿀 경우에는 다시 다른 조건이 된다.
이번 검토 문서가 이전 준비 기록의 “0.75 결과 대기” 상태를 갱신한다. 원본과 당시 기록은
보존했으며 commit/push는 하지 않았다.
