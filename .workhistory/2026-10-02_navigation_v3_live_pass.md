# 경로 여유 수정 후 Luna와 G1의 목표 도달 성공 검토

2026-10-02 UTC. 사용자가 실행한 `clearance-recovery-v3` 결과를 읽기 전용으로 검토했다.
동일 장면에서 로봇은 10회 호출 예산 중 5회의 navigate_to만 사용해 원래 목표를 달성했다.
결과는 검증된 VALID / PASS / GOAL_REACHED다. 복구·밀기는 사용하지 않았으므로 해당 기술의
실제 성공 근거로 세지 않는다. 이 검토에서는 실행 코드나 원본 결과를 변경하지 않았고 새 유료 실행도 하지 않았다.

## 실제 행동과 이동

GPT는 다섯 번 모두 최종 목표 `[7, 0]`으로 10초 navigate_to를 선택했다. 별도 plan_path
조회, raw move, push_object, request_skill은 없었다. 경유점은 로봇 내부 계획기가 계산했고
AFS/평가기에서 정해진 우회 행동을 주입하지 않았다. 기존 GT 기하·자세 기반 계획 조건이다.

행동 사이 간격에는 모델 추론과 기존 자세 유지가 포함된다. 두 번째 행동은 기존 이산
0.005초 적분/부동소수점 경계로 10.005초가 기록됐다. 추가 복구 예산이나 종료 후 grace가
배정된 것은 아니다. 마지막 행동은 원래 마감 72.515초 전에 성공했다.

모든 navigation_trace의 사건 목록은 비어 있고 복구 횟수·행동 내부 재계획 횟수는 0이다.
각 navigate_to 시작 시에는 정상적인 최초 경로 계획을 수행했다. 이를 재계획 0회와 혼동하지 않는다.
차단 motion 샘플도 모두 0이다. 이번 성공은 막힌 뒤 복구한 사례가 아니라 막히지 않고 통과한 사례다.

상자는 XY 약 6.08e-9m만 변해 수치 오차 수준이다. 물체 이동이나 밀기 성공을 관측하지 않았다.

## 경로 여유와 체류 조건

저장 기하로 계산한 계획 격자점의 최소 AABB/바닥 거리(정확한 시작·끝 연결점 제외)는
0.53559m다. 실제 navigate_to 상태 표본의 최소 거리는 약 0.47410m로 기본 발자국 0.40m보다
약 7.41cm 바깥이었다. 이는 20Hz 상태 표본과 첫 기하 스냅샷으로 계산한 2D 지표이며
전신 최소 간격이나 200Hz 전체 궤적의 보증은 아니다. 상자 이동은 사실상 없었다.
정확한 시작·끝 연결점을 포함한 계획점 최소 거리는 0.49309m다. 추가 여유 안쪽의 실제
시작점을 원래 발자국으로 연결할 수 있도록 설계한 부분이지 목표를 다른 좌표로 바꾼 것은 아니다.

이 기록은 추가 여유를 둔 새 추종기가 이번 장면에서 차단 없이 진행했다는 근거다.
여유 증가만이 성공의 유일한 원인이라는 인과 실험은 아니며, 복구 branch는 실제로 실행되지 않았다.

목표 계약은 `[7, 0]`에서 반경 0.25m 안에 연속 1초 체류하는 것이다. 마지막 평가기는
66.815초에 약 1.000초를 기록했다. 표시된 미세한 부족분 약 9e-13초는 부동소수점 오차다.
20Hz 마지막 상태 표본은 66.800초라 dwell이 0.985초지만, full-rate 종료 평가와 모순되지 않는다.

`goal_dwell_v1`의 도구 도착 반경 0.12m에는 66.800초에 진입했고 `navigate_goal_hold`가
0.015초 실행됐다. 앞선 대부분의 1초는 목표 반경 0.25m 안에서 접근하는 동안 누적됐다.
최종 영역에 서서 추가로 1초 동안 자세를 유지한 실험은 아니다. 도착-체류 연결이 이번 실행에서
작동한 것은 확인하지만 장시간 hold 안정성이나 마지막 호출 예산 경계 상황의 일반 해결은 미검증이다.

## AFS 근거와 사용량

`analyze_behavior`의 states/events/actions/object_motion은 모두 AVAILABLE이고 경고는 없다.
`compact_evidence`의 action_timeline에 다섯 행동의 이동량·차단 0회·복구 0회·재계획 0회가
전달되는 것도 확인했다. 이번 실행의 0회는 관측값이며 과거 누락된 측정치를 0으로 바꾸지 않았다.

사용량 감사는 OBSERVED, 확인 5/5, 누락·충돌 없음이다. 관측 입력 토큰 107481,
출력 토큰 1276이다. 이는 제공자가 반환한 사용량이지 달러 청구액 확정이나 가격 비교가 아니다.
이번 실행은 로봇 API만 사용했고 AFS 모델 호출은 없었다.

이 PASS는 새 로봇 조건의 개발/회귀 성공 기준선 후보로 사용할 수 있다. 과거 FAIL과는
로봇 코드 조건이 다르므로 동일 조건의 PASS/FAIL boundary로 묶지 않는다. 원래 동결 AFS
캠페인의 FAIL/FDR/Gain을 수정하지 않았고 새 표본으로 끼워 넣지도 않았다. 캠페인의
자기 arm/seed 이력 제한을 우회해 외부 성공을 몰래 warm history로 주입해서도 안 된다.

## 영상과 다음 작업

- `report.html` 및 `rollout.mp4`가 있다. MP4는 H.264, 960×540, 12fps, 802프레임, 66.833초다.
- GIF는 없으며 재생성을 하지 않았다. 기존 정책 카메라 004는 직접 확인했지만 전체 영상 재생을
  완료했다고 주장하지 않는다. 이 검토에서 새 시각화나 실험 산출물을 만들지는 않았다.
- 검토 후 실행 코드는 그대로 두고 이번 조건을 고정한다. 소수의 동일 장면 반복으로 성공 재현성을
  확인한 뒤, AFS에서 통로 폭·장애물 배치·마찰 중 한 축씩 대조하며 새로운 실패 경계를 탐색하는
  것이 다음 방향이다. 반복과 확장은 별도 호출 예산을 확인하고 실행한다.
- 복구 branch 자체를 검증하려면 별도의 명시적 시험이 필요하다. 이 한 성공으로 복구·밀기·점프
  능력이나 모든 장면에서의 보행 성공을 주장하지 않는다. AFS를 그 작업 완료까지 미루지는 않는다.

확인 사실과 미검증 능력을 구분해 이력·사용 안내·workspace memory를 갱신했다.
원본 실험 폴더와 실행 코드는 보존했고 커밋·push는 하지 않았다.
