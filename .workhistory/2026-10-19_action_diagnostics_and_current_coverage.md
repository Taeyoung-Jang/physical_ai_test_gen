# AFS 행동 진단과 신규 집합 기준 선택 구현

## 목적과 변경

미분류 실패 7개 분석 후 사용자가 승인한 AFS 개선을 구현했다. 새 `feedback_policy: action-diagnostics-v1`은 expanded-ten-v1과 failure-branch-v3에서만 명시적으로 활성화된다. 기존 기본값은 legacy다. 로봇, 목표, 평가기, 유형 정의·임계값, 장면 도메인, 호출·토큰·시뮬레이션 시간 조건은 변경하지 않았다.

`action_diagnostics.py`는 검증된 전체 action_window에서 경로 거절 수, 최초 거절과 증거 참조, 같은 목표 좌표의 반복 거절, 목표 영역 밖에서 반환한 중간 목표 도착, 조작 요청 유무를 만든다. AVAILABLE 여부와 censored 결과를 구분한다. 자료가 없으면 UNAVAILABLE이며, 결과가 잘린 경우 조작 미관측을 완전한 부재로 취급하지 않는다. 거절된 push 요청도 요청 관측일 뿐 실제 물리적 밀기 수행이나 성공으로 취급하지 않는다.

`failure_objective.py`는 외부 이력, 신규 시도, 누적 유형을 나눠 전달한다. 새 모드의 `missing_supported_families`는 이번 세션 신규 시도의 측정 유형을 기준으로 하므로 기존 호스트 정렬이 신규 집합의 미발견 유형을 우선한다. 측정 계산기와 한 실패 장면당 한 대표 유형 집계는 그대로 재사용한다. PASS나 예측 유형은 신규 발견이 아니다.

전체 행동 진단은 제시된 행동 증거와 최근 가설 검토에 들어가며, 반복 행동을 동반한 실패 횟수도 과거와 신규로 나눈다. 이는 겹치는 행동 통계이지 새로운 실패 유형이 아니다. LLM 요청은 같은 행동이 반복되면 다른 허용 기준 장면·배치와 예상 행동을 검토하고, 조작을 하지 않았다면 물리적 조작 가설을 미검증으로 다루도록 안내한다. 새로운 자동 행동 강제, 원인 판정, 다른 방 구조·지형 생성, 새 hard gate는 추가하지 않았다. 기존 breadth 배정, 범위·중복 검사와 bounded rejection은 유지한다.

## 새 설정

`scene2test/config/afs_behavior_diversity_luna.json`은 Luna, 유효 12개 목표, 최대 16회 시도, AFS 20요청, 축당 최대 4회, 반복 0회, history_limit 4, 300초 응답 대기를 유지하면서 새 피드백만 활성화한다. 이는 별도 새 세션용이며 COMPLETE numeric_recovery 세션을 연장하거나 소스 변경을 우회해 재개하지 않는다. 실행 명령과 무료 plan 명령은 `scene2test/docs/AFS_BREADTH_SEARCH.md`의 새 절에 있고 루트 README에도 연결했다.

## 검증

- 관련 CPU 합성 회귀 133개 통과, 최종 32.29초. 새 진단, 누락·부분 자료, 거절 요청, 과거·신규 유형 구분, 중복 참조 비가산, 실제 측정과 예측 분리, 기존 모드, 저장 응답 중단 재개를 검증했다. mock proposer/runner만 사용한 테스트의 live=True는 실제 API·로봇 호출이 아니다.
- 초기 테스트 하나에서 Python tuple과 JSON list의 직접 비교가 실패했다. 기능 문제가 아닌 불필요한 테스트 가정이어서 제거했으며 최종 관련 검사를 다시 통과했다.
- 미분류 실제 7개 저장 메모리에 새 함수를 읽기 전용 적용했다. 경로 거절 수는 00000/00001/00005/00006/00007/00010/00011 순으로 2/2/2/3/4/2/2회이며 전부 조작 요청 미관측이다. 종료 시간 창 바깥의 거절도 행동 진단에 보이고, 대표 실패 유형은 바뀌지 않는다.
- API 키를 제거한 프로세스에서 실제 FAIL attempt_00000과 PASS attempt_00002로 development_plan이 통과했다. 같은 e8ec811981448476f029536ee0b49be2fcad786c53d86edc3a5ba5105813bd5b 로봇 조건, 최대 160회 로봇 호출 상한이다. DB·세션은 생성하지 않았다.
- 실제 완료 보고서의 전체 저장 메모리로 다음 컨텍스트와 요청을 메모리 내 구성했다. 과거 3종(goal_completion_failure, goal_occupied, manipulation_failure), 신규 발견 0종, 신규 미발견 지원 유형 8종이 구분된다. 이 메모리에는 그 세션의 외부 이력도 포함하므로 과거 행동 통계는 원래 신규 12개만의 통계가 아니다. 제시된 4개 행동 증거에 진단이 들어가고 요청은 233,503 UTF-8 bytes다. 이는 토큰·청구량 또는 wire capture가 아니며 전송하지 않았다.
- Ruff 검사와 형식 검사, git diff --check 통과. 기존 사용자 변경을 보존했다.

실제 유형 다양성이나 비용 개선은 아직 검증하지 않았다. 새 유료 실험, API·GPU·로봇 실행, 기존 DB·결과·라벨·예산 변경, 커밋·push는 하지 않았다. 문서 작성 지침은 결론·검증·미검증 성능을 구분하고 기존 작업 이력 목적지에 기록하는 데 적용했다.
