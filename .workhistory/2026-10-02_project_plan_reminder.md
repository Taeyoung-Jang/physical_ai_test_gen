# 전체 연구 개발 계획과 현재 위치 리마인드

2026-10-02 UTC. 사용자는 세부 다음 작업을 정하기 전에 전체 계획을 다시 확인하도록
요청했다. 이 문서는 새 기능 설계의 확정이나 구현 착수가 아니라, 기존 목표·설계·구현·
실험 근거를 구분한 현황 정리다. 직전에 제안한 과거 기준 장면 선택은 AFS 개선 후보
하나이며 전체 로드맵을 대체하거나 최우선 작업으로 확정하지 않는다. 폭 실험 중단은 유지한다.

## 1 최종 목표

주어진 로봇 시스템과 최초 task goal에 대해, 로봇이 목표를 달성하지 못하는 환경을
제한된 시험 예산으로 효율적이고 다양하게 찾아내고, 그 조건을 재현 가능한 행동 검증·
회귀 테스트 자산으로 만드는 것이 목표다. 평가 대상은 정책만이 아니라 관측, 내부
계획기, 실제 설치된 기술, 저수준 제어기를 포함한 로봇 시스템 전체다.

G1은 현재 검증 대상이다. 장기적으로 교체 가능한 로봇/정책 실행 어댑터와 공통 결과
계약을 지향하지만, 현재 구현이 어떤 로봇이든 즉시 연결하는 범용 제품이라는 뜻은 아니다.
G1 보행·밀기·점프 성능을 끝없이 개선하는 것이 본 연구의 산출물은 아니다.

기준 목표와 정량 지표는 [Failure_Case_Goal](../.blueprint/Failure_Case_Goal.md),
판정 철학은 [목표 중심 AFS 설계](../scene2test/docs/GOAL_OUTCOME_AFS_DESIGN.md),
단계별 기준은 [측정 구현 계획](../scene2test/docs/FAILURE_CASE_MEASUREMENT_PLAN.md)을 따른다.
날짜별 문서의 미구현 언급은 해당 시점의 상태이며 현재 코드와 최신 검토로 보완해야 한다.

## 2 유지할 책임 경계

- AFS는 허용된 환경 조건과 다음 실험을 선택한다. 로봇의 경유점·행동·밀기 방향을
  평가자가 지정하지 않는다. 실패 가설이나 정답 경로를 로봇에게 전달하지 않는다.
- 로봇은 원래 가진 관측과 능력으로 방법을 선택한다. 현재 예는 카메라와 GT 지도/상태를
  받는 GPT 정책, 내부 경로 계획기, CUDA GR00T 보행 및 제한적 밀기 실행의 조합이다.
  카메라만 쓰는 end-to-end VLA나 SLAM 기반 시스템을 검증한 것으로 표현하지 않는다.
- 평가기는 최초 목표를 실제 상태로 판정한다. 접촉·낙상·no_path는 관찰이지 즉시 FAIL이 아니다.
  회복 후 목표를 이루면 PASS, 고정 예산 소진 또는 로봇의 종료 시 유효한 목표 미달이면 FAIL이다.
- API timeout·깨진 시뮬레이션 등 실험 장애는 INCONCLUSIVE다. 미완료 기록에 성공/실패를
  추정해 넣지 않는다. 안전 사건과 목표 결과, 실패 유형·원인 가설도 별도로 기록한다.
- 로봇 모델·프롬프트·관측·목표·예산을 바꾸면 새로운 비교 조건이다. AFS가 후보마다
  로봇 속도나 목표·시간 제한을 바꿔 억지로 실패시키는 방식은 사용하지 않는다.

## 3 전체 처리 흐름

```text
Task goal + 로봇과 관측 명세 + 허용 scene space
    → 초기 장면 선택
    → SceneSpec에서 SceneGraph / 지도 / 물리 장면 생성과 검증
    → 평가 대상 로봇이 자율 실행
    → 목표 판정 + 행동 시계열 + MP4 + 비용 저장
    → AFS가 근거와 가설을 갱신하고 다음 탐색 공간 선택
    → 새 장면 생성과 실행으로 반복
    → 실패 메모리 / 경계 후보 / 회귀셋 / 비교 보고서
```

LLM AFS 입력은 scene space와 SceneGraph, 로봇·정책·가용 기술·관측 조건, task goal,
허용 변경 범위와 예산, 실제 이전 성공/실패 및 행동 근거다. 출력은 새로운 탐색 부분 공간,
조건 범위 또는 후보와 가설·근거·실험 목적이다. 코드는 제안을 검사하고 장면을 생성하며
실제 rollout이 결과를 결정한다. LLM의 설명이나 확신은 관측 실패·보정된 실패 확률이 아니다.
현재는 별도 모델 학습보다 이력 문맥을 갱신하는 LLM-guided search가 중심이다.

## 4 전체 구성 요소의 계획과 상태

| 구성 | 최종적으로 할 일 | 현재 상태와 남은 범위 |
|---|---|---|
| 환경과 SceneGraph | 제어 가능한 다양한 장면과 물리·관계 표현을 일관되게 생성 | 미로/방/지형 생성 경로는 존재. 현재 GPT goal-agent AFS와 직접 연결된 범위는 통로·동적 상자 1개·정적 블록 2개의 17축 |
| 로봇 실행과 계약 | 로봇이 자신의 정책과 기술로 goal을 실행하고 조건을 고정 | G1/Luna/CUDA 실행 및 일부 장면 성공 검증. 범용 로봇 교체·새 grasp/jump는 미완료 |
| 목표 평가와 행동 관측 | 결과와 과정, 중단을 구별해 측정 | 목표-only 판정, 시간선·물체 이동·계획 피드백·manifest·사용량·MP4 구현. 모든 행동 원인 자동 진단은 아님 |
| 적응형 실패 탐색 | 실제 행동을 보고 실패 발견·완화·경계·대조·독립 탐색·반복 배정 | LLM 제안·행동 피드백·가설 우선 선택·중복 억제·캠페인 구현과 소규모 live 실행 있음. 다양한 장면에서의 일반적 효율은 미입증 |
| 실패 유형과 회귀 자산 | 서로 다른 실패 유형을 근거로 분류하고 버전 변경 때 재검사 | failure memory·관측 bracket·실행 가능한 회귀 도구 존재. 세 operational 규칙만 부분 지원, 외부 로봇 자산까지 완전 휴대 복원은 아님 |
| 공정 비교와 연구 보고 | 같은 조건/예산에서 Random 대비 FDR·Gain·Coverage·비용 보고 | 계산기·보고서·소규모 비교 있음. 다중 seed 독립 평가와 4/6 실제 발견 근거는 미완료 |

SceneSpec/SceneConfig가 원본이며 그래프만 바꾸고 물리 장면을 그대로 두지 않는다.
SceneGraph와 지도는 역할이 다르다. 그래프는 객체·관계·속성을, 지도는 경로 계산에
필요한 기하·점유를 제공한다. 통제 가능한 합성 시뮬레이터에서 먼저 이 정보를 직접
생성하기로 했으며, raw point cloud/mesh의 segmentation·classification이나 일반 SLAM을
선행 과제로 삼지 않았다. 실사 입력은 이후 별도 입력 어댑터/인식 과제다.

17축에는 상자 질량·마찰·바닥 마찰·통로 폭·상자 측면 위치와 두 블록의 위치·크기·높이·
회전이 포함된다. 경사·계단 생성 코드가 별도로 있다는 사실을 이 goal-agent backend가
이미 모두 실행한다는 뜻으로 확대하지 않는다. 단일 축 대조는 해석을 위한 현재 모드이며,
장기 설계의 여러 요소 상호작용·다양한 레이아웃 탐색을 영구 금지한 것이 아니다.

기존 Panda/PyBullet, G1 HTTP navigation, expanded terrain, 로컬 GPT goal-agent는
구현 범위가 다른 경로다. client 저장/실행 부품은 재사용하지만 전체가 하나의 완성된
서비스나 대시보드로 통합됐다고 하지 않는다. 현재 연구 중심은 로컬 goal-agent AFS다.

## 5 합의한 연구 단계

| 단계 | 목적 | 현재 위치 |
|---|---|---|
| P0 | 판정·분모·비용·출처와 지표 계산 계약 | 기본 구현됨 |
| P1 | 행동 근거·반복 결과·실패 메모리·재현 자산 | 기본 구현됨, 유형/이식성 등 확장 여지 있음 |
| P2 | 행동 기반 AFS와 Random의 예산 고정 실행·관측·다음 선택 | 구현·소규모 live 확인됨, 탐색 품질 개선·검증 계속 필요 |
| P3 | 장면/관측 범위와 실패 유형 측정 확장, 회귀 실행 | 부분 구현. 유형 4/6을 발견·검증할 범위는 아직 부족 |
| P4 | 개발과 분리된 seed로 방법·조건을 동결한 비교 평가 | 본격 평가 미완료 |

P0/P1/P2 기반이 존재하므로 매번 처음부터 새 파이프라인을 만드는 단계가 아니다.
P3의 장면/유형 확장은 P2의 작은 비교가 모두 끝날 때까지 기다릴 필요가 없다.
P4를 하기 전에는 지원 범위와 분류 규칙을 검증하고 로봇·탐색 조건을 고정해야 한다.

## 6 최종 평가 지표

| 지표 | 의미 | 목표 |
|---|---|---|
| FDR | 유효 완료 rollout 중 goal FAIL 비율 | 30% 이상 |
| 상대 Gain | (AFS FDR − Random FDR) / Random FDR | 20% 이상 |
| Diversity Coverage | 증거가 있는 서로 다른 실패 유형 수 | 사전 정의 6종 중 4종 이상 |

6종은 충돌, 도달 불가, 장애물 간섭, 목표 위치 점유, 작업자 안전 위험, 인식 오류다.
코드의 현재 세 규칙은 collision·obstacle_interference·goal_occupied의 시간적 연관
측정이며 원인 확정이 아니다. unreachable·human_safety_risk·perception_error는 미지원이다.
규칙 3개 구현은 유형 3개 발견이 아니며, 관측된 실패 패턴 수를 공식 Coverage로 바꾸지 않는다.
현재 지도/관측 조건과 장면 생성 범위가 해당 유형을 실제 시험할 수 있는지도 함께 확인해야 한다.

기존 6+6 장애물 파일럿의 AFS 6 FAIL 대 Random 5 FAIL/1 PASS는 관측 상대 Gain 20%였지만
단일 seed·한 실패 차이이고 과거 로봇 조건이다. 현재 버전의 일반 우월성이나 최종 연구 목표
달성 근거가 아니다. 4/6 달성은 확인되지 않았다. 반복도 예산에 포함하고 고유 실패 수,
첫 발견 비용, 경계 근거, 실패 유형, 제외·미상 비용을 함께 공개해야 한다.

## 7 최근 실험의 위치와 다음 논의

최근 보행·경로 추종 수정과 폭 대조는 평가 대상이 기본 장면에서 작동하는지 확인하고
성공 측면 근거를 확보한 개발 검증이다. 4.0m PASS 3회, 3.6m PASS 1회, 3.2m는
API 중단으로 판정 보류다. 사용자는 여기서 폭 실험을 멈췄으며 재시도를 요구하지 않는다.

다음 우선순위는 전체 목표에 대해 비교해야 한다.

- AFS 선택 품질: 행동 근거가 실제로 더 유용하고 다양한 후보 선택으로 이어지는가.
  직전의 과거 anchor 선택은 이 안의 세부 개선 후보이며 아직 최우선으로 확정하지 않는다.
- 장면과 유형 범위: 현재 연결된 환경·관측·측정으로 무엇을 발견할 수 있고, 4/6 목표에
  무엇이 빠졌는가. 센서·관측 조건을 바꾸면 별도 로봇 조건이고, 유형 이름만 추가할 수 없다.
- 재사용과 검증: 발견 사례가 반복 결과와 불확실성을 보존한 회귀 자산으로 남는가.

전체 계획을 상기한 이번 턴에서는 어느 기능부터 구현할지 새로 확정하지 않았다.
새 paid rollout, 로봇 기능 확장, 기존 campaign 재개, DB 상태 변경은 하지 않았다.
write-page 스킬의 구현/실험/계획 구분 원칙으로 이 이력과 색인, 로드맵 안내,
workspace memory만 업데이트했다. 커밋·push는 하지 않았다.
