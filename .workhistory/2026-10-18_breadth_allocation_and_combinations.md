# 환경 요소 실행 배정과 두 요소 조합 탐색 구현

## 요청과 변경 범위

사용자는 미발견 실패 유형 우선, 서로 다른 환경 요소의 실제 실행 배정, 작은 변경과 큰 변경 및 조합 탐색 병행, 같은 접근의 연속 PASS 이후 전환을 구현하도록 요청했다.

새 `exploration_policy: breadth-v1`을 기존 failure-branch-v3의 명시적 선택 사항으로 추가했다. 기존 설정과 단일 축 계약은 유지한다. 로봇 정책, 목표, 평가 규칙과 측정 임계값을 바꾸지 않았다. 미발견 유형 우선순위는 기존에도 있었지만 실행이 배치에 편중됐으므로, 이번에는 제안 자체가 아니라 실행 배정 계약을 추가했다.

## 구현 내역

- `methods/breadth_policy.py`: 바닥 물성, 물체 물성, 장애물 형상, 배치, 사람 배치의 다섯 묶음과 실제 시도 횟수를 추적한다. 사용 가능한 묶음 중 덜 실행한 묶음에 다음 슬롯을 배정한다. 동률은 위 순서로 결정하며 랜덤이 아니다.
- 새 슬롯은 작은 단일 변경, 큰 단일 변경, 두 요소 조합 순서로 반복한다. 현재 설정에서 작은 변경은 전체 축 허용 폭의 10% 이상 30% 미만, 큰 변경은 30% 이상이다. 조합은 서로 다른 두 묶음에서 각 축 최소 10%를 바꾼다. 큰 값 또는 큰 차이 자체가 더 높은 실패 가능성을 의미하지 않는다.
- `BreadthPoint`/`BreadthProposal`: 첫 변경은 axis/value, 두 번째 변경은 필수 `extra_changes` 목록으로 표현한다. 단일 변경은 빈 목록, 조합은 원소 하나만 허용한다. 기존 모델은 이 필드를 거절한다.
- 조합은 같은 실제 관측 기준 장면에서 출발한다. challenge/transfer는 unmixed PASS, relief는 관측 FAIL 근거를 사용한다. 각 축의 범위, 최소 변화, 쿼터와 직전 사용 제한, 전체 장면의 중복, 근거와 소스 일관성을 검사한다. 선언하지 않은 값은 그대로 둔다.
- 조합 한 회는 로봇 시도 하나지만 두 축과 두 묶음 모두의 사용 횟수에 반영된다. 중단이나 제외도 원래 시도 예산을 소비한다.
- 연속 신규 유효 PASS 두 개가 같은 예측 유형이면 다음 선택에서 그 예측 유형을 잠시 제외한다. 두 PASS에 공통 환경 묶음이 있으면 가능한 다른 묶음을 우선 배정한다. 제외/미완료를 PASS나 FAIL로 취급하지 않는다. 이는 다음 가설 전환이지 실패 유형이 불가능하다는 판정이 아니다.
- 배정 조건 통과 후 미발견 측정 유형, 의도, 해당 예측 유형의 시도 횟수, 묶음 횟수, 신규성, 제안 순서로 선택한다. 예측은 실제 발견 유형으로 집계하지 않는다. 실제 측정 피드백은 검토 이력과 신규 이력을 사용하지만 성과 분모는 신규 유효 실험으로 분리한다.
- `exploration_allocation`, 후보별 `exploration`, `changed_axes`, 모든 적격 후보의 `breadth_comparison` 정렬 점수와 선택 여부를 저장한다. 조합의 branch_audit에는 두 축의 전후 값을 기록한다. 이벤트에도 두 축을 남기고 HTML 보고서에서 확인할 수 있다.
- 조건 불일치는 명시적 후보 거절로 기록하고 동일 슬롯에서 남은 AFS 요청 예산으로 새 제안을 받는다. 유효 대안이 있으면 재호출 없이 선택한다. 슬롯 변경, Random 대체, 자동 장면 수리 또는 모호한 요청 재전송은 없다. 범위·스키마·전송 오류의 중단 정책은 그대로다.

환경 변경은 실험 시작 전 고정한다. AFS가 실행 중 장면을 바꾸거나 로봇의 행동을 지정하지 않는다. 이번 구현은 현재 20축 환경의 변화와 조합을 넓힌 것이며, 계단·경사·새 방 구조·움직이는 사람을 새로 연결한 것은 아니다.

## 새 설정과 예산

`scene2test/config/afs_breadth_luna.json`:

- Luna, HTTP 300초, history_limit 4, expanded-ten-v1.
- 유효 12개 목표, 최대 16회 시도, AFS 요청 최대 20회.
- 축별 최대 4회, 명시적 반복 0회, 최소 변화 비율 .1.
- 회당 10회 호출의 기준 로봇이면 최대 160회 로봇 호출이다.

이는 새로운 별도 개발 세션의 설정이며 이전 세션 예산을 늘리는 변경이 아니다. 이 작업에서 새 유료 세션을 실행하지 않았다. 기존 COMPLETE 세션의 남은 슬롯을 소비하거나, 소스 변경을 무시하고 기존 세션을 재개해서는 안 된다. 토큰 상한, 숨겨진 시뮬레이션 시간 상한이나 실패 판정 완화를 추가하지 않았다.

## 검증

새 CPU 합성 테스트 27개가 통과했다. 작은 변경과 큰 변경 및 조합의 요청 스키마/호스트 일치, 엄격한 필수 필드, 두 번째 축의 범위·최소 변화·중복·쿼터 검증, 두 묶음 동시 차감, 잘못된 조합 거절, 연속 PASS 가설 전환, 전체 루프/보고서, 저장된 조합 응답의 무재전송 재개, 후보 거절 후 같은 슬롯의 예산 내 새 제안을 검증했다. 합성 PASS/FAIL은 테스트 배선 검증용이지 실제 발견 성과가 아니다.

최종 관련 CPU 회귀 테스트는 303개 모두 통과했다(107.81초). 새 모드 외에 기존 분기, 확장 유형 연결, 재제안, 자동 루프, 실패 지향 선택, 단일 값 제안, 행동 메모리, 지표, 회귀 자산, 확장 분류와 기존 요청/CLI를 포함한다. 수정한 Python 7개 파일의 Ruff 정적 검사와 포맷 검사, git diff --check도 통과했다. 초기 합성 루프 테스트는 제안기가 두 PASS 뒤 같은 가설을 계속 내어 요청 예산 소진으로 끝났으며, 새 전환 계약을 따르는 테스트 제안기로 수정한 후 통과했다. 실행 코드가 거절 조건을 완화한 것은 아니다.

실제 완료 세션 `20261018T134620_116429Z`의 유효 6개 아카이브(attempt 0/2/3/4/5/6)로 development_plan 및 초기 memory/context/request를 읽기 전용 구성했다. 기존 로봇 조건 `e8ec811981448476f029536ee0b49be2fcad786c53d86edc3a5ba5105813bd5b`가 일치했다. 초기 배정은 floor_physics/small이고 현재 미발견 지원 유형은 collision, obstacle_interference, human_safety_risk, fall, locomotion_stall이다. 요청 본문 직렬화 크기는 약 206KB였고 AxisChange/BreadthPoint 스키마가 구성됐다. 이 값은 전송 캡처나 토큰 수가 아니다.

전송, GPU/로봇 실행, 새 runtime 세션/DB 생성은 없었다. 기존 아카이브와 결과, 예산, 레이블을 수정하지 않았고 커밋/push도 하지 않았다. 새 소스는 연구 프로토콜의 재귀 소스 해시 범위에 포함된다. 실제 LLM의 새 계약 준수율, 비용, 네 번째 실패 유형 발견과 FDR 개선은 아직 측정하지 않았다.
