# 실패 발견 목표에 맞춘 행동 기반 AFS 선택 개선

## 사용자 목표와 변경

사용자는 PASS도 나올 수 있지만 실제 실패를 찾아내도록 탐색해야 한다고 강조했다.
작은 실험 횟수를 채우는 것보다 실패율30%와 근거 기반4종을 함께 찾는 방향을 우선한다.
새 opt-in failure-directed-v2를 추가했다. 기존 v1 세션/결과/예산/기록은 수정하지 않았다.

새 FailurePoint/FailureProposal은 관찰 근거ID, 취약 조건, 예상 목표 실패 과정,
변경 방향 이유, 탐색 의도, 예측 유형을 필수로 요구한다. 방향을 바꾸어 경로가 달라질
수 있다는 설명만으로는 부족하다는 프롬프트를 추가했다. 단, 호스트는 자연어의
물리적·인과적 옳음을 검증하지 않으며 이는 구조와 선택 휴리스틱 개선이다.
OpenAI Docs 지침에 따라 공식 structured outputs 문서를 확인해 required 전체
필드와 additionalProperties=false를 유지했다. 모델/추론강도/토큰cap을 바꾸지 않았다.
출처: https://developers.openai.com/api/docs/guides/structured-outputs

failure_objective.py는 검토된 VALID 이력과 새 VALID 결과의 측정상 가족 집합,
PASS/FAIL 수, 선택된 근거의 수치 행동 요약, 최근 가설의 관측 결과를 만든다.
예상 유형은 실제 발견 유형과 분리한다. PASS는 유효하며 목표 실패가 관찰되지 않은
근거로 다음 제안에 반영한다. FAIL도 원인 입증으로 표시하지 않고 제외는 FAIL로 쓰지 않는다.

호스트 순위는 intent, 미발견 측정 유형, 같은 예측 유형의 시도 수, 축 시도 수,
제안 순서, 신규성이다. v1의 최소 사용 축만 허용하는 마스크는 v2에서 제거했다.
직전 축 cooldown, 축별2회, 최소10% 변화, 중복/도메인/근거 검증은 유지한다.
실제 FAIL이 없는 relief는 거절하며, 최근3회 내 relief도 제한한다. 비교 가능한
PASS 없이 FAIL2개 이상일 때 허용된 relief를 우선하고 그 외 새 메커니즘/도전을 우선한다.
이 제한은 실패 악화 반복을 피하기 위한 탐색 정책이지 성공을 강제하는 평가 기준이 아니다.

기본 설정6유효/8시도 및 별도20유효/24시도 설정을 추가했다. 로봇은 Luna10호출,
goal_dwell_v1/밀기활성/HTTP300/시뮬레이션무제한 그대로다. 어떤 로봇 행동도 AFS가
지정하지 않는다. 실제4종 관찰·30%·Gain을 이번 구현의 성과로 주장하지 않는다.

## 검증

합성 검사: PASS만 있어도 도전 제안 가능, 추측을 실제 유형에 반영하지 않음,
필수 예측/실제근거/반증·변경이유 스키마, unknown/일반case만 근거 거절, 완화 게이트,
축쿼터/cooldown/최소변화/범위/컨텍스트, 유형별 순위, 재개 무중복과 기존 목표 판정 보존.
초기 새 테스트14개, 기존 모드65개가 통과했다. 최근 가설 결과 피드백과 설정 검사를
추가한 최종 통합 회귀는 **224 passed in 48.11s**. Ruff와 diff 검사도 통과했다.

실제 입력 아카이브20261018T004636_410637Z 및 point_recovery/attempt_00001/rollout으로
plan 검증 통과. 같은 정규화 로봇 조건e8ec8119..., v5/20축이 유지된다. 오프라인 요청은
두 실제 PASS ID를 포함하고 관찰FAIL0/허용intent mechanism_transfer,challenge다.
행동 근거/예측/방향 이유가 required이며 미발견 지원유형4개를 표시했다. JSON직렬화
최초 요청은86111 UTF-8 bytes였고, 이후 남은 시도와 유효 목표를 별도 숫자로 추가했다.
입력 PASS는 새 유효 목표를 소모하지 않는다는 검사도 추가했다. 마지막 확인에서
새 모드 **17 passed in 13.50s**. API0/로봇0/새런타임세션0이며 과거 타임아웃은 FAIL로
가져오지 않았다.

기존 동결 recovery 세션은 새 코드로 이어 실행하지 않는다. 새 버전은 새 세션으로
실행해야 하며 과거 아카이브를 입력 이력으로만 재사용한다. 기존 구버전 예산을
자동 연장하거나 결과를 다시 분류해 덮어쓰지 않았다. 유료 실험·commit·push는 없다.
