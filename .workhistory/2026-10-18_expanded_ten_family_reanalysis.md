# 실패 유형 10종 확장과 기존 실험 사후 재분석

## 승인과 범위

실제 시뮬레이션에서 기존6종만으로 설명하기 어려운 현상을 관찰하여 분류 대상을
늘리자는 사용자 요청을 반영했다. 사용자는 정의 확장과 기존 실험 재분석부터 진행하는
계획을 승인했다. 신규4종은 넘어짐·이동 정체·물체 조작 실패·목표 완료 실패다.
분류 대상을 늘린 것과 실제4종을 관측한 것은 구분한다.

평가 원문 `.blueprint/Failure_Case_Goal.md`에 다양성 목표를10종 중4종으로 변경하고,
2026-10-18 확장 이유와 기존 결과 보존 원칙을 기록했다. FDR30%·Random 상대 Gain20%
목표는 그대로다. 같은 목표·서로 다른 환경의 전체 표본에서 유형을 집계한다.

## 구현

- `research_records.Family`에4개 ID를 추가하되 기존 `FAMILIES`6개는 유지하고 별도
  `EXPANDED_FAMILIES`10개를 정의했다. 기존 기본 측정·프로필은 바뀌지 않는다.
- `evaluation/expanded_taxonomy.py`의 새 프로필 `expanded-goal-behavior-v1`은 기존
  goal-behavior-v2 규칙4개와 신규4개를 사용한다. 도달 불가·인식 오류는 여전히 미지원이다.
- 넘어짐: 연속 상태에서 base Z<.45m 또는 tilt≥60도가 .5초 이상. 상태 gap>.25초면 UNKNOWN.
  이는 현재 G1 시뮬레이션의 운영상 진단 규칙이지 보편적인 자세·안전 기준이 아니다.
- 이동 정체: 최근10초 내 끝난 이동 실행이2초 이상이며 순이동≤.05m, 구간 위치 편차≤.1m.
  추론 대기·의도적 정지·제자리 회전·target_reached·짧은 막힘은 정체로 만들지 않는다.
  실행 시간·이동량·상태 범위가 부족하면 UNKNOWN이다. 왕복 후 복귀도 편차 검사로 거절한다.
- 물체 조작 실패: 실제 accepted 조작 호출의 물체별 마지막 도구 결과가 알려진
  rejected/failed/failure/aborted 상태인 경우. 나중의 성공은 앞선 거절을 대체한다.
  실행 거절도 포함하므로 질량·물리적 밀기 능력의 부족이 확인됐다는 뜻이 아니다.
- 목표 완료 실패: full-rate 최종 goal_progress가 계약 반경·체류 시간과 일치하고
  영역 안이지만 필요한 dwell을 채우지 못한 경우. 모든 예산 종료를 이 유형으로 세지 않는다.
- VALID FAIL에서만 대표 유형1개를 집계한다. 기존 유일 대표를 우선 보존하고 기존
  ambiguous는 강제로 해소하지 않는다. 대표가 없으면 fall→goal_completion_failure→
  locomotion_stall→manipulation_failure 순서로 하나를 고른다. 나머지 관측은 보조 진단이다.
  이 우선순위는 집계 규약이며 실패 원인 입증이 아니다.
- `calculate_discovery_metrics`는 명시적인10종 inventory를 받을 때만 분모10으로 계산한다.
  구버전 기본값은6종이다. 임의 inventory는 거절하고, 미지원·미분류가 있으면 전체
  coverage=null/관측 하한만 제공한다. HTML의4/6 고정 문구도 활성 분모를 따르게 했다.
- `tools/reanalyze_failure_types.py`는 개별 `--run` 또는 완료된 `--session`을 읽는다.
  세션 보고서 manifest와 각 rollout의 해시를 확인하며 별도 경로에 기존6종·새10종 지표와
  episodes/taxonomy/JSON/CSV/HTML/manifest를 저장한다. 덮어쓰기·원본 내부 저장은 거절한다.

## 실제 재분석 결과

원본: `/workspace/g1_failure/runtime/afs_autonomous/20261018T081720_637822Z`의 신규6개 rollout.
입력 성공·실패 warm history는 추가하지 않았다. 새 결과:
`/workspace/g1_failure/runtime/failure_type_reanalysis/20261018T130328_693125Z/report.html`.

| 항목 | 기존6종 | 새10종 사후 분석 |
|---|---|---|
| 유효 실험 | 6 | 6 |
| PASS/FAIL/제외 | 3/3/0 | 3/3/0 |
| FDR | 50% | 50% |
| 분류된 유형 | 0 | 1 |
| 미분류 실패 | 3 | 2 |
| 관측 유형 하한 | 0/6 | 1/10 |

회차3만 대표 `goal_completion_failure`로 분류했다. 최종 거리.218747m로 반경.25m 안이지만
dwell .655/1초다. 같은 회차의 과거 unsupported_box_face는 `manipulation_failure`
보조 진단으로 보존하고 별도 발견 유형을 더하지 않았다. 다른 두 FAIL은 미분류다.
기존 PASS/FAIL은 바뀌지 않았고, 원본 보고서가 표시한0종도 덮어쓰지 않았다.

원본 선언 아카이브436개 해시가 일치하며 새 보고서5개 artifact 해시도 일치했다.
새 보고서는 이전 실행 비용을 다시 표시한 것이지 새 유료 사용이 아니다.
이 결과는 과거 데이터를 새 기준으로 설명한 것이며 prospective AFS 성능이나4종 달성이 아니다.
대표1개 집계 원칙상 이번3FAIL만으로4종을 달성하는 것은 불가능하다.

## 검증과 문서

초기 신규/기존 측정 테스트75개 통과 후, 전체 관련 CPU/synthetic 테스트223개가58.50초에
통과했다. 신규11개에는4개 유형의 양성/음성/누락, 대기와 실제 실행 구분, 왕복 오인 방지,
후속 성공, PASS·제외 비집계, 여러 진단의1개 대표 집계, 기존 대표 보존,6/10 분모 분리,
별도 보고서·덮어쓰기 방지를 포함한다. Ruff/format 및 git diff 검사를 통과했다.

안내 문서는 `scene2test/docs/EXPANDED_FAILURE_TYPES.md`, README에 진입 링크를 추가했다.
문서 작성 스킬 지침에 따라 확장 이유·판정 범위·관측값·실적 한계를 기록했다.

## 남은 작업과 경계

현재 구현은 승인한1번 유형 정의/검출과2번 재분석이다. 기존 live AFS 선택기·프롬프트는
아직6종 계약이며 새4개 유형을 자동으로 목표 삼아 탐색하는 연결은 다음 단계다.
이 연결은 새로운 조건과 별도 예산으로 검증해야 한다. 기존 완료·동결 세션은 재개하지 않는다.
기존6종 규칙의 종료 정체·접촉·노출 임계값은 느슨하게 바꾸지 않았다.
목표·로봇 동작·모델·예산·완료 판정·원본 DB/아카이브/결과는 변경하지 않았다.
이번 작업에서는 API·GPU·로봇·새 시뮬레이션·commit/push를 실행하지 않았다. GIF는 만들지 않았다.
