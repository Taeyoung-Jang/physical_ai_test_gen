# 과제 목표 대비 구현과 실험 검증 현황

2026-10-16 UTC. 핵심 자동 실패 탐색의 개념 검증은 완료했지만, 과제가 요구하는
탐색 효율과 실패 유형 다양성의 종합 달성은 아직 입증하지 못했다. 현재 위치는
연구용 자동 실행 기반을 확보하고 선택 품질과 평가 범위를 검증하는 단계다.
최신 확인된 자동 탐색 실험은 2026-10-03 결과이며, 검토한 runtime의 자동 탐색·비교·
회귀 폴더에서 그 이후 신규 세션은 확인되지 않았다.

## 과제 목표와 책임 경계

[원래 평가 목표](../.blueprint/Failure_Case_Goal.md)는 고정된 로봇 시스템이 최초 목표를
달성하지 못하는 환경을 효율적이고 다양하게 찾고, 행동 근거와 재현 조건을 회귀 자산으로
남기는 것이다. G1의 보행·조작 능력을 계속 개선하는 것이 과제의 최종 산출물은 아니다.

AFS는 환경을 바꾸고 로봇은 행동을 선택한다. 평가기는 최종 목표 달성 여부를 판정하며,
API 중단과 유효한 목표 실패를 구분한다. 접촉이나 정적 경로 없음만으로 FAIL을 만들지 않는다.

## 구현 성취도

| 구성 | 현재 확보한 것 | 남은 범위 |
|---|---|---|
| 환경과 SceneGraph | 장면 설정에서 그래프·지도·물리 장면 생성, 현재 goal-agent AFS의 18개 변경 축 | 통로·상자·두 블록 중심이며 별도 미로·지형 생성기가 이 루프에 모두 연결된 것은 아님 |
| 로봇 자율 실행 | 카메라와 GT 지도/상태를 받는 GPT 정책, 내부 계획기, CUDA 보행, 실제 목표 도달 기록 | 범용 로봇 어댑터 완성이나 카메라 전용 VLA·SLAM·점프 검증은 아님 |
| 목표와 행동 측정 | PASS/FAIL/INCONCLUSIVE, 행동 시계열, MP4, 출처 해시, 사용량, 종료 진단 | 모든 실패 원인의 자동 확정이나 완전한 6종 분류는 아님 |
| 행동 기반 AFS | 이력을 읽어 가설·환경을 선택하고 실행·결과 반영을 반복하는 자동 루프 | 실패 도전·완화·경계 확인의 배분, 기하 근거, 특정 중단 지점 재개 오류 |
| 회귀 테스트 자산 | failure memory, 성공/실패 반복 기록, 관측 구간, 재실행 도구 | 새 발견 사례의 충분한 반복과 체계적 회귀셋 확립, 외부 자산의 완전 휴대 복원 |
| 연구 평가 | FDR/Gain/부분 유형 계측과 AFS/Random 실행·보고 도구 | 현재 방법을 고정한 다중 seed 독립 평가와 4종 이상 발견 근거 |

P0 계측 계약과 P1 행동 메모리는 기본 구현을 갖췄고, P2 자동 탐색은 소규모 실제 실행을
확인했다. P3 장면·유형 범위와 회귀 검증은 부분 완료, P4 독립 성능 평가는 미완료다.
개발 항목별 비중과 최종 검증 분모가 정해지지 않아 전체 완료율을 임의의 백분율로 환산하지 않는다.

## 실제로 확인한 핵심 성과

[첫 자동 AFS 검토](2026-10-03_afs_autonomous_live_review.md)의 여섯 시도는 모두 VALID였고,
PASS 5회·FAIL 1회·제외 0회로 종료됐다. AFS 5회, 로봇 52회 호출로 네 축을 탐색했다.
실패 후 상자를 옆으로 완화해 PASS를 얻었고, 성공·실패 사이 X 중간값도 확인한 다음
다른 장애물 축으로 전환했다. 사람이 다음 수치를 매번 지정하지 않는 흐름이 실증됐다.

새 실패는 10회 호출 종료 시 목표 반경 안에 있었지만 요구 체류 1초 중 0.27초만 채운
사례다. 목표 미달이라는 평가 계약상 유효한 실패지만 밀기·낙상·인식 실패의 근거는 아니다.
이 여섯 실험에서는 밀기나 기록된 낙상·비바닥 접촉이 없었다. 관측된 성공/실패 구간은
단회 근거이며 재현 확률이나 확정된 물리 경계가 아니다.

## 정량 목표와 현재 증거

| 지표 | 목표 | 현재 판단 |
|---|---|---|
| 실패 발견율 FDR | 30% 이상 | 최신 개발 탐색의 단순 관측값은 1/6, 약 16.7%. 완화·경계 검사를 포함한 외부 이력 기반 개발 세션으로 최종 성능 평가는 아님 |
| Random 대비 상대 Gain | 20% 이상 | 과거 단일 seed 파일럿은 AFS 6/6 실패, Random 5/6 실패로 관측 Gain 20%. 한 건 차이이고 이전 로봇 조건이라 현재 방법의 일반 우위는 미입증 |
| 실패 유형 다양성 | 정의된 6종 중 4종 이상 자동 발견 | 현재 지원 규칙은 collision·obstacle_interference·goal_occupied 3종. 구현 개수는 발견 개수가 아니며 4/6 달성은 미입증 |

과거 비교에서 FDR/Gain의 숫자상 목표를 관측한 사실과, 현 방법이 목표를 안정적으로
달성했다고 주장하는 것은 다르다. 현재 개발 세션에는 Random 대조군이 없고 외부 이력이
있으므로 과거 비교군과 합쳐 Gain을 계산하지 않는다. 최신 FAIL에는 지원된 유형 규칙이
검출되지 않았다. 네 축 변경을 네 실패 유형 발견으로 세지 않는다.

도달 불가·작업자 안전 위험·인식 오류 규칙은 아직 미지원이다. 작업자 근접 측정은 설계와
오프라인 참조 계산기가 있지만 실제 사람 장면·trace·검증된 분류 규칙 연결이 남아 있다.
기존 규칙도 시간적 연관의 측정이며 인과관계 확정은 아니다. 유형 범위는 가장 명확한
구조적 공백이다. 실패율만 높여서는 다양성 목표를 충족할 수 없다.

## 다음 우선순위

1. **AFS 안정성과 선택 품질 보완.** 저장 응답 검증 전 중단 시 nested JSON key order로
   동일 요청을 다르게 보는 재개 오류를 먼저 고치고 중단 회귀 테스트로 검증한다. 성공
   장면에서의 도전, 실패 장면에서의 완화, 구간 확인을 균형 있게 배분한다. 실제 goal
   점유와 계획기 여유, 최종 체류·예산을 구분해 가설 입력에 제공한다. 로봇을 임의로
   수정하거나 판정을 약화하는 작업은 아니다.
2. **실패 유형과 회귀 자산 확장.** 적어도 네 번째 유형의 장면·관측·판정 계약을 연결하고
   양성/음성 근거로 검증한다. 기존 세 규칙도 실제 사례로 확인한다. 안전 사건 자체로
   goal PASS를 FAIL로 바꾸지 않는다. 대표 성공·실패를 예산 고정 회귀셋으로 관리한다.
3. **조건을 고정한 본 평가.** 개발 이력과 분리된 여러 seed에서 동일 환경 범위·로봇·
   판정·예산의 AFS/Random을 실행한다. FDR/Gain/유형 수뿐 아니라 반복·제외·고유 사례·
   비용·불확실성을 함께 보고한다. 관측 결과가 목표보다 낮아도 그대로 보존한다.

이는 후속 우선순위이며 이번 현황 요청으로 새 구현이나 유료 실행을 시작한 것은 아니다.
중단한 폭 실험을 재개하거나 사용자에게 다시 수동 수치 변경을 반복하도록 요구하지 않는다.

## 확인 범위와 기록

현재 코드의 `failure_taxonomy.RULES`는 세 항목이며 `discovery_metrics.py`에 FDR·상대 Gain과
부분 coverage 처리가 있다. `afs_autonomous.py`의 `_finish_proposal`에는 raw request 비교가
남아 있어 이전에 발견한 재개 취약점이 수정된 것으로 간주하지 않았다. 최신 자동 보고서
`runtime/afs_autonomous/20261003T165928_663622Z/reports/20261003T173419_661417Z/summary.json`을
다시 읽어 완료·판정·비용을 확인했다. 이번에는 원본 전체 재해시나 새 테스트 실행을 하지 않았다.

저장소는 점검 시작 시 clean이었다. 이 현황 기록과 색인만 추가하며 코드·실험 DB·원본·
평가 결과·동결 예산을 변경하지 않는다. 추가 API/GPU/로봇 실행, 커밋·push도 하지 않는다.
